# Frontend pages — `Frontend/mintly/src/pages/`

Route entries only — one page per route. If a piece of UI is (or is about to be) used by more than one page, extract it to `src/components/` first. Global rules: repo-root `CLAUDE.md`; frontend-wide commands, `api.ts`, shared modules, styling, conventions, gotchas: `Frontend/mintly/CLAUDE.md`; shared components: `src/components/CLAUDE.md`.

- `Home.tsx` — landing page (10a/10d redesign): a two-column **hero** (grid `1.05fr .95fr`, collapses to one column and hides the fan under 960px) — left column is a three-line display headline ("Your cards. / Their prices. / One portfolio.", hard `<br>`s), the restyled `HeroSearch` pill, and a short sub-copy; right column is the fanned spread of the 151-set starter Special Illustration Rares (Blastoise/Charizard/Venusaur ex — `sv3pt5/200,199,198`). Then a **proof strip** of four facts (`21,400+` catalog / `Daily` refresh / `Unlimited` scans / `$0`) — 4-up with full-bleed hairline rules on desktop, a rounded 2×2 box under 640px; the catalog figure is the `CATALOG_SIZE` constant (no public count endpoint — bump it as the catalog grows; the real number is Admin → Data health). Then the **mint-accented scanner section** (`scan*` classes): eyebrow / "Scan a stack in one sitting" / copy, two "Free forever" / "Unlimited scans" badge pills, a mint "Scan a card" button, and the decorative corner-bracket card visual — laid out with explicit grid placement (copy top-left, button under it, card spanning the right) so the single-column mobile order becomes copy → card → full-width button (DOM order is copy, visual, button). Finally the cream **CTA** band, auth-aware: "Create a free account" (→ `/login` register) signed out, "Open my portfolio" signed in. The `.home-features` numbered feature cards and the hero divider are **gone** (the proof strip + scanner carry that weight). App-wide layout: a dark outer frame (`--frame`) with all routes rendered on one large rounded panel (`.main`); the sticky navbar merges into the frame (translucent + blurred) — favicon leaf logo + wordmark on the left, the nav pill (Search/Scan/Portfolio) centered on the screen (3-column grid; flex on phones), and on the right a circular profile avatar linking to `/profile` when logged in, or a "Log in" text link + a cream "Sign up" pill when not (there's no navbar logout button — logout lives on the Profile page). It auto-hides: slides up when scrolling down past 80px, slides back on any upward scroll (`navbar-hidden` class toggled by a scroll listener in `Navbar.tsx`). `App.tsx` also renders a site-level JSON-LD `@graph` (Organization + WebSite with a `/search?q=` SearchAction + WebApplication) on every route, built from `window.location.origin` — there is no configured public URL, so the markup stays correct on any host; `index.html` carries the static descriptive `<title>` and meta description.
- `Search.tsx` — debounced (400ms) search-as-you-type; **seeds query + filters from the URL** (`?q=`, `?set=`, `?rarity=`, `?type=`, `?number=`) on mount and **mirrors them back into the URL** as they change via `setSearchParams(..., { replace: true })` (replace, so typing doesn't stack history). That two-way sync is what makes the home hero's `?q=` link work, makes searches shareable/bookmarkable, and — the reason it exists — makes browser **Back from a card return to the exact search** (Search remounts and re-seeds from the params) instead of the default view; each card tile also passes the current search string as router `state` (`backSearch`) so CardDetail's "← Back to Search" link returns there too. **Chrome (8a/8b redesign):** one rounded **search pill** (glyph + transparent input + a round clear ✕ when non-empty + a cream Search submit); a **filter row** where set/rarity/type are **multi-select** facets — each is a `<select>` chip that stays put so you can keep adding, plus one dismissible accent chip (`{label} ✕`) per chosen value (a styled `<select>` can't carry a working ✕, and already-picked options drop out of its dropdown); a facet ORs its values (any of the chosen sets/rarities/types) while different facets AND together. Card # is always a 78px input chip; a `Clear` text button and a right-aligned `N results` count follow. The chosen facets serialize to the URL comma-joined (`?set=a,b`), and `filterCards` sends them to `/cards` as repeated params (`?set_id=a&set_id=b`). The header is either the **default-view** block (eyebrow `Newest set` + set name + `Released {date} · {n} cards`, shown when nothing is typed and no filters) or a **results** row (`Results for "{q}"` + `Page p of n · sorted by relevance`). The **tile** is left-aligned: artwork (with a top-left `✓ Owned ×N` badge when held — see `owned.ts`), name + `{set} · #{number}` meta, a `--text-h` price with the full `DayChange` (amount + percent, shown even on a flat day) on its own line below it, and a full-width `+ Portfolio` outline button that reveals the inline `PriceQtyForm` quick-add (price/qty row + Add/Cancel) via `useAddCard`, preceded by a `PortfolioPicker` (shown only with 2+ portfolios; defaults to the active one, retargets the add). `useAddCard.add` takes the target id as its 4th arg. Cards with no TCGPlayer price show the backend's `estimate` with a muted `eBay est.` label (add form pre-fills it); nothing at all shows an em dash. Loading shows 10 skeleton tiles (never an empty page); a successful-but-empty search shows a centered "No cards match …" block (with a Clear-filters pill when filtered) rather than an error. The pager (restyled outline pills, centered, disabled in `--slash`) renders above and below the grid; any query/filter change resets to page 1, and page moves skip the debounce. (Deliberately following the portfolio precedent, the mobile filter **bottom sheet** and the `Biggest movers`/`Most valuable` default-view **sort pills** from the prototype were skipped — the sheet needs a second breakpoint against the app's one-breakpoint convention, and a page-only client sort would be a misleading control; the inline chips already reflow and native selects are good on mobile.)
- `Scan.tsx` — route `/scan` (authed; when logged out shows the `SignedOutHero` promo — `variant="scan"`, advertising free unlimited scans — instead of a plain login prompt, since `/scan` is login-only server-side); the camera card scanner. A live rear-camera viewfinder (`CameraViewfinder`) whose capture crops to a canvas uploaded to `POST /scan` (`scanCard` in `api.ts`) and matched by CLIP image embedding — no OCR, no on-device text reading. A **Single / Batch add** toggle (the shared `.segmented` control, `--cream`-selected) sits in the page header beside the `<h1>`; single mode is the default. `matchScore` (CLIP cosine) is made visible everywhere as a rounded percentage; `SCAN_CONFIDENCE_FLOOR` (~0.85, tune against real captures) is the shaky threshold; a card with no score (pre-backfill) shows no badge. **Batch mode** is a two-column layout (`.batchBody`, flex-wrap, camera-first when it collapses; the camera column is `position: sticky` only ≥900px so it can't pin over the queue once stacked): the live viewfinder on the left, a live queue on the right. Each scan **prepends** the top guess to the queue (newest on top) — nothing is written until "Add all N to portfolio" posts one `addCardBatch` to the portfolio chosen in the queue header's `PortfolioPicker` (with `allowCreate`, so a new portfolio can be spun up inline for the batch). The queue header carries a count+summed-total pill, the target `PortfolioPicker`, and a two-step "Clear all"; a `--warn` banner counts low-confidence rows; each row pairs your capture thumbnail with the matched art (`your scan → match`), a confidence badge (green "N% match" / amber "Check this · N%"), editable price/qty, a "Change" button opening `CandidatePickerModal` (amber on shaky rows), and a remove ✕. Partial failures stay in the queue with a `--negative` border (cleared when the row is edited); leaving batch mode with a pending queue uses a two-step inline confirm. **Single mode** after a capture is a two-column result: a capture column (your photo + "Scan another" + "Not it? Search by name") beside a wide best-guess card ("We think this is…" + confidence badge, name/meta/price with `DayChange`, an always-visible inline add row + "Card page ↗" link) and an "Other matches" grid whose tiles mirror the Search result tile (art + confidence chip, name/meta/price, inline `PriceQtyForm`/`useAddCard` add). The captured image is sent to the backend to compute the match (not stored) — `Privacy.tsx` §4 documents this. Amber lives in the `--warn*` tokens (`index.css`).
- `CardDetail.tsx` — route `/card/:cardId`; a two-column hero — big card image on a soft accent glow (left); on the right the name, a bold price with its `DayChange` and a source tag (`TCGplayer market` / `eBay est.`), a buy box (Add-to-Portfolio, price pre-filled, with a `PortfolioPicker` above the form — shown only with 2+ portfolios — to pick the target, plus two outbound links side by side below a divider — "Buy on TCGplayer ↗", href from `tcgplayerBuyLink` in `src/affiliate.ts`: the card's stored `tcgplayer.url`, else a name+number TCGplayer search, wrapped in the Impact affiliate link + `rel="sponsored"` when `VITE_TCGPLAYER_IMPACT_LINK` is set and the destination is tcgplayer.com; and "Search on eBay ↗", href from `ebayBuyLink`: an active-listings eBay search for the card's name + collector number, EPN-tagged + `rel="sponsored"` when `VITE_EBAY_EPN_CAMPAIGN_ID` is set — a muted "Mintly may earn a commission" line appears under the buttons when either link is affiliate-tagged), a KPI stat-tile row (Market/Low/Mid/High), and fact chips (rarity/type/HP/artist/released). Under the set meta line, when the user owns **≥1** card from this card's set, a `SetCompletionMeter` (`getOwnedSetCompletion()` from `setCompletion.ts`, account-wide + cached, matched on `card.set.id`) shows "Your {set}" completion linking to `/search?set=<id>`; adding this card refetches it (via the add's `onSuccess`) so the meter appears/updates immediately, and it's hidden when signed out or none of the set is owned. Below, full-width: a `PriceHistoryChart` (fed `currentVariantPrices` — each variant's live market/mid — and an `onData` callback that hands the fetched history back for the table), then an "All price variants" table shown only for cards with 2+ TCGPlayer variants — each row shows Low/Mid/High/Market plus a **Today** column: a per-variant `DayChange` chip computed client-side from the variant's history series (the same rule as the backend's `change_baselines`; an em dash until that variant has a prior-day row). On narrow screens the columns stack (image → name → price → buy box → tiles → chips → chart), verified overflow-free to 360px. An **Other versions** section (full-width above the chart, shown when the card shares its set + number with others — fetched via `filterCards({set_id, number})`) cross-links the regular card and its stamp/mark varieties, each a card of its own; a forked card also carries a **Variety** badge beside its name (`card.varietyOf`). When the backend flags the card `refreshing` (stale catalog price being re-fetched), the page re-polls `getCard` up to 3× at 3s intervals and swaps in the fresh price when it lands — the add form's pre-fill follows only if the user hasn't typed over the auto-filled value, and the `PriceHistoryChart` (passed `currentPrice={market ?? ebay?.median ?? null}`) re-overlays its newest point. When the card has no TCGPlayer price it fetches `/cards/{id}/ebay-price` and renders the estimate in the SAME layout, source-adapted: the eBay median takes the price slot with the `eBay est.` tag plus an "Estimated from N recent eBay sold listings · dates · informational only" line, and the KPI tiles become Median/Average/Low/High. The add form is seeded with the median (so priceless cards are still addable); that median also feeds the chart's `currentPrice`, and the endpoint snapshots it so the DB stays in step. Sets `document.title` to "\<card\> · \<set\> - Mintly" once the card loads (restored to `DEFAULT_TITLE` — which must match the static `index.html` title — on unmount) and renders schema.org `Product` JSON-LD via `StructuredData` (`cardJsonLd`): name/image/description/sku/brand — **no `offers` block at all**, since Mintly is a tracker, not a store.
- `Portfolio.tsx` — **scoped to the active portfolio** (`usePortfolios()` from `src/portfolios.ts`): an outer component resolves the active id and renders `<PortfolioView key={activeId} portfolioId={activeId}>`, so switching portfolios remounts with fresh state (no synchronous `setState` in an effect — same trick as `Holding.tsx`). The header carries a `PortfolioSelector` (switch/create/rename/delete — it's the visible title) beside the `PortfolioCsv` kebab (passed `portfolioId` so import lands in the active portfolio). `reload()` calls `getPortfolio(activeId)`/`getPortfolioHistory(activeId)`. When logged out shows the `SignedOutHero` promo (`variant="portfolio"`) instead of a plain login prompt (`PageMessage` still backs the loading/error states); otherwise a **hero panel** (portfolio value with a dimmed-cents span and an all-time gain/loss pill; a 2×2 stat grid — cost basis, cards·lots, today's total move, best %-mover; and a value-over-time `AreaChart` with a `1M/6M/1Y/All` segmented range toggle that filters the fetched history client-side, anchored to the latest snapshot so the purity lint stays happy), a **filter row** (name input, an All/Gainers/Losers `segmented` control replacing the old `<select>`, a sort `<select>`, and a right-aligned cards·lots count), then a **holdings grid** of link-wrapped tiles — the *whole tile* is a `<Link to="/portfolio/:cardId">` (artwork full-bleed via a `.tile-art > span` override of `CardImage`'s 160px cap, name, `Qty N`, market price + a `DayChange today` chip, footer of paid/avg-paid + group `GainLoss`) — ending in a dashed **"Add a card"** cell → `/search`. Grid grouping + per-card metrics come from `src/portfolio.ts` (`groupByCard`/`groupMetrics`), shared with the Holding route. **All per-lot editing/removal moved to `Holding.tsx`** — the grid no longer expands lots or carries edit/remove state. Sort keys (recently added [default] / highest value / biggest gain / biggest loss / name) and the gainers/losers filter are computed per card *group*; cards without price data sort last and match neither. Summary figures always reflect the full portfolio, not the filtered view. Above the hero, a right-aligned **`PortfolioCsv`** kebab (⋮) menu offers Export CSV (client-side download of one row per lot) and Import CSV (bulk-seed/restore via `addCardBatch`); it also renders in the empty-portfolio branch (Export disabled, Import active) so a collection can be seeded from a CSV. Import re-runs the page's extracted `reload()` on success. Below the holdings grid, a **Set completion** section (`getSetCompletion(portfolioId)`, fetched inside `reload()` so it's scoped to the active portfolio) lists one row per owned set — set name/series + a `SetCompletionMeter` (with percent) — each row a `<Link to="/search?set=<id>">` to fill the gaps; hidden when the fetch returns nothing.
- `Holding.tsx` — route `/portfolio/:cardId` (authed; logged out → `SignedOutHero variant="portfolio"`), everything about *your position* in one card. An outer component keyed by `cardId` remounts the inner one when paging between holdings (state resets without a synchronous effect `setState`, same trick as `PriceHistoryChart`). Layout: a **breadcrumb + prev/next pager** (walks the portfolio's recent order — derived from `getPortfolio()` — and honors ←/→ keys when no field is focused, disabled at the ends), a two-column body (260px `CardImage size="detail"` sidebar + a "Card page & market data ↗" link to `/card/:id`, beside the main column), a **title row** (name + `×N owned` pill + `{set} · #num/total · N purchases since {first}` sub-line + a cream **Add purchase** button that reveals the shared `PriceQtyForm` pre-filled to market), an **accent-bordered position panel** (Your value + `DayChange today` = day change × qty; Cost basis + avg; Total P&L + %; Market now + source label reusing `getCardPrice`; plus a cost-basis bar placing market on the paid min→max scale, **hidden for single-lot holdings**), a **Purchases table** (one row per lot with per-lot P&L, inline Edit/Remove with the same two-step confirm + self-clearing `StatusMessage` errors as the old Portfolio, a totals row, wrapped in `overflow-x:auto`), and a full-width **"Market price vs. your cost"** `PriceHistoryChart` (`segmentedRange` + `avgCost` reference line + per-purchase `dots`). No new endpoint — `getPortfolio(activeId)` (scoped to the active portfolio via `usePortfolios()`, then filtered to this card's lots — so the position and prev/next pager reflect the portfolio you came from) + `getCard()` for name/set/market; the Add-purchase form targets the active portfolio. Removing the last lot navigates back to `/portfolio`; an id with no lots shows a "You don't own this card yet" prompt linking to `/card/:id`. (One data gap: the portfolio endpoint carries no set name, so the *grid* tile meta shows only `Qty N` — the Holding page gets the set name from `getCard`.)
- `Profile.tsx` — route `/profile` (authed; shows the same login prompt as Portfolio when logged out). **12a/12b redesign:** the page moves onto the shared rounded panel with an **identity header** (a 64px initials-monogram avatar, the username as the `<h1>`, a "Member since {created_at}" meta line, and outline **Admin**/`Log out` pills on the right — Admin only when `profile.is_admin`, the sole place the dashboard is linked; Log out clears the token and redirects to `/login` with the "logged out successfully" notice), then a `196px 1fr` grid: a **sticky section rail** (a `<nav aria-label="Profile sections">` of anchor links to the panel ids, active item driven by an `IntersectionObserver` over the panels; collapses to a horizontally-scrolling chip row below 860px) beside a column of **panels**. Loads `GET /auth/me`; panels: **Account details** (username + email side by side; Save is a cream pill that greys to a disabled slug with "No changes yet" beside it until a field changes, then sends only the changed fields via `updateProfile`; below the form an **email-verification row** shows "Email verified" or "Email not verified" + a "Resend verification email" button wired to `resendVerification`, keyed on `profile.email_verified`; plus a **Connected accounts** row listing linked social providers (`profile.oauth_providers`) as chips when any exist), **Password** (for a **social-only account** — `has_password` false — the change-password form is replaced with a note pointing at the Forgot-password page to set one, while Sign out of other devices stays available since it doesn't need a password; otherwise: current / new / confirm, each with an inline **Show/Hide** toggle, plus a three-segment **strength meter** under New password mirroring the register form's rules — the standalone hint is gone; changing the password swaps in the fresh token `changePassword` returns, so the current tab stays logged in. Below the form a **"Sign out of other devices"** control calls `signOutOtherDevices` — the leaked-token kill switch, which revokes every other session and re-issues this one's token), **Accessibility** (the shared `AccessibilitySettings` component — reduce-motion / high-contrast / underline-links `role="switch"` toggles + a Default/Large/Larger text-size radiogroup, applied instantly and persisted to localStorage; extracted from this page so the public `/accessibility` route can host the same controls), and the `DeleteAccount` danger panel as the fourth section (`id="delete"`). The card-count in the mock's meta line is intentionally dropped (no count is in hand and the handoff says not to add a request for it). Statuses use the shared `StatusMessage` line; a 401 anywhere redirects via `useSessionRedirect`. `PasswordField`/`SettingToggle` are module-local helpers in the page file.
- `Admin.tsx` — route `/admin` (authed + admin), the private site-stats dashboard behind `GET /admin/stats`: a header with the generated-at time and a Refresh button, stat-tile sections (Users — total/new 7d/new 30d/with-a-portfolio incl. a percent-of-accounts sub-line; Portfolios — portfolios count/lots/distinct cards/total quantity; Data health — catalog cards, last full crawl, stale prices, snapshot rows, snapshots today, database size), a mint single-series bar chart of signups over the last 30 days (recharts, zero-filled days, same recessive grid/tooltip styling as `PriceHistoryChart`), and a recent-signups table (username/email/joined/lots) in an `overflow-x:auto` box. Every denied state — no token, an expired session (`SessionExpiredError`), and the stats call's 404 (`NotAdminError`) — renders the shared `NotFoundMessage`, the same view the catch-all route shows for any unknown URL. That's deliberate: no login prompt and no `useSessionRedirect` here (the app-wide convention's one exception), since either would reveal an authed page exists at `/admin`. An admin whose session lapsed just logs in at `/login` and returns via Profile → Admin. Timestamps are naive UTC and anchored with `Z` before formatting (same rule as Portfolio's `parseUTCDate`).
- `Login.tsx` — combined login/register (11a/11b redesign): a two-column grid, form left + an aria-hidden illustrative **portfolio preview** right (marked "Example", real Base-Set `CardImage` art + sample prices via the shared `DayChange`; the preview drops below 720px). The form is bare on the panel (no card border): a big display heading + subtitle, a fit-content **segmented tab pill** (Log in / Register), labeled `<label>` fields (14px-radius inputs, the app's only 14px controls, with a mint focus ring), a password field whose wrapper carries the border + `:focus-within` ring so an inline **Show/Hide** toggle (`aria-pressed` + stable `aria-label`) sits inside it, and a full-width cream submit. **Login tab:** "Forgot password?" → `/reset-password`, plus a "New to Mintly? Create a free account" line under submit that swaps to the register tab (no navigation). **Register tab:** a decorative three-segment **password strength meter** (bars `aria-hidden`, fill left→right as the length/letter/number rules pass; the rules line is the `aria-describedby` description) and the Terms/Privacy checkbox. Client-side password validation mirrors the backend. Opens on the Register tab when navigated to with router `state={{ register: true }}` (the `SignedOutHero`'s "Create a free account" link), otherwise the Login tab. Shows a notice when redirected here via router state — "Your session expired…" (from `useSessionRedirect`), "You've been logged out successfully." (from the Profile page's Log out button), or "Your password has been updated…" (from a completed reset). Above the form (both tabs) sits the `SocialSignIn` component (Google/Microsoft buttons — renders nothing when no provider is configured); a bounced social sign-in returns to `/login?oauth_error=<code>` and the page maps the code to a message via `OAUTH_ERRORS` (seeded into the error state on mount).
- `OAuthCallback.tsx` — route `/auth/callback` (unauthed), where the backend redirects the browser after a successful social sign-in. Reads the JWT from the URL **fragment** (`#token=` — never sent to a server, kept out of logs/Referer), `setToken`s it, `clearPortfolios()` + `invalidateOwned()` (fresh account, drop any prior cache), and navigates to `/portfolio` with `replace` so the token leaves no history entry; a missing token bounces to `/login` with a notice. Failures never reach here — the backend redirects those to `/login?oauth_error=…` instead (handled by `Login.tsx`).
- `ResetPassword.tsx` — route `/reset-password` (unauthed), one page with two modes keyed on the `?token=` search param. Without a token: an email form that calls `forgotPassword` and swaps to the backend's generic "if that email has an account…" confirmation (plus a 30-min/spam-folder hint) — the only surfaced error is the 429 rate-limit detail. With a token (arriving from the reset email): new-password + confirm fields mirroring the backend rules client-side, calling `resetPassword` and routing to `/login` with the "password updated" notice; an invalid/expired-link 400 renders inline with a "Request a new link" link back to the tokenless mode. Each mode keeps its own state so switching can't leak errors across.
- `VerifyEmail.tsx` — route `/verify-email` (unauthed — the link from the verification email works whether or not the browser is logged in). Reads `?token=`, calls `verifyEmail(token)` once on mount (status seeded from the token's presence so the no-token case needs no effect `setState`), and shows verifying / success / failure. Success links to `/portfolio`, failure points to the Profile resend. Styled to match the reset card (`VerifyEmail.module.css`). Registration sends the email server-side, so this page only handles the click-through; the durable verification surface (badge + resend) is the Profile page.
- `NotFound.tsx` — the `path="*"` catch-all route: any URL no other route matches (`/taco`) renders the shared `NotFoundMessage`. Client-rendered, so the HTTP status is still 200 (Caddy's SPA `try_files` serves `index.html` for every path) — normal for an SPA; the "404" is the view, not the status code.
- `Accessibility.tsx` — public accessibility statement (route `/accessibility`, linked from the `Footer`). Uses the `.legal-page` shell like Terms/Privacy, states the WCAG 2.1 AA / ADA conformance target, and **embeds the shared `AccessibilitySettings` component** so the display preferences (reduce motion / high contrast / underline links / text size) are usable without an account, not only from the signed-in Profile page. Lists real features + honest known limitations and gives the `mintlytcg@gmail.com` feedback contact. Keep its claims true when a11y behavior changes (same "tracks reality" rule as the legal pages).
- `Terms.tsx` / `Privacy.tsx` — static legal pages (routes `/terms`, `/privacy`), linked from the `Footer` component. Terms §3 and Privacy §§3–4 carry the affiliate disclosures ("may earn a commission" wording, so they're true whether or not the affiliate ids are configured; Privacy §3 notes affiliate cookies are set by the retailer only after leaving Mintly). Privacy §4 discloses the full third-party data path: Pokémon TCG API / TCGCSV / eBay lookups, affiliate click-through attribution, the email provider, and Cloudflare fronting the site. Keep them in sync with behavior changes (see the root `CLAUDE.md` "legal pages track reality" convention).

Deeper cross-page runtime behaviors (catalog-first serving, the daily-change baseline rule, eBay-estimate flow) are in HANDOFF "Behaviors worth knowing".
