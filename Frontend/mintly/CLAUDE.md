# Frontend — `Frontend/mintly/`

React 19 + TypeScript + Vite + React Router 7 + Recharts. Global rules live in the repo-root `CLAUDE.md`. Page/component detail loads automatically when you work in it: `src/pages/CLAUDE.md`, `src/components/CLAUDE.md`.

## Commands

Run from `Frontend/mintly/` — NOT the repo root:
```bash
npm run dev            # Vite dev server on :5173
npm run build          # tsc + vite build — use this to verify changes compile
npx eslint src/        # lint
npm test               # Vitest watch mode
npm run test:run       # Vitest single run (what CI/verification should use)
npm run test:typecheck # type-check the test suite (tsc -p tsconfig.test.json)
```
The API base URL comes from `VITE_API_BASE` (baked in at build; unset defaults to `http://localhost:8000`).

## Tests

Vitest + React Testing Library (jsdom) with **jest-axe** for accessibility, wired into `vite.config.ts`'s `test` block; global setup is `src/test/setup.ts`, shared helpers (`renderWithRouter`, a `LocationProbe`, and a preconfigured `axe`) are in `src/test/utils.tsx`. Tests are **co-located** as `*.test.ts(x)` beside the code they cover. Coverage today (40 files / 279 tests): the shared logic modules (`format`, `portfolio`, `variants`, `affiliate`, `accessibility`, `owned`, `setCompletion`, `grading`, `portfolioCsv`), the module-less presentational components, `CardImage`/`Footer`/`Navbar`/`HeroSearch`/`PageMessage`/`SocialSignIn`/`SetCompletionMeter`, the shared `AccessibilitySettings`, the static `Accessibility`/`Terms`/`Privacy` pages, AND every interactive route page (`Home`, `Search`, `CardDetail`, `Portfolio`, `Holding`, `Watchlist`, `Login`, `Profile`, `Scan`, `Admin`, `ResetPassword`, `OAuthCallback`, `VerifyEmail`, `NotFound`) — each with an axe no-violations check. Page tests mock `../api` with the `importActual` spread (stub only the network fns / token accessors; keep pure helpers + error classes real) and drive navigation through `renderWithRouter`'s `LocationProbe`; charts, the live-camera capture path, and Profile's IntersectionObserver highlighting are left uncovered by design (jsdom can't render/measure them — Scan's tests drive the file-upload capture fallback instead). The full rendered pages were also audited live with axe-core against the dev server (Home/Login/Accessibility/Privacy all clean); when changing shared color tokens or adding pages, re-run that live audit rather than trusting jsdom (jsdom can't compute color contrast).

- Scripts pin `TZ=UTC` so the date-formatting helpers assert deterministically — run tests via the npm scripts, not a bare `vitest`, or the local-time assertions in `portfolio.test.ts` will drift.
- Test files are **excluded from the production build** (`tsconfig.app.json`) so `npm run build` stays scoped to shipped code; they're type-checked separately by `tsconfig.test.json` (`npm run test:typecheck`) and by Vitest at runtime.
- `setup.ts` installs an in-memory `localStorage` (Node's experimental global one is inert under jsdom) and stubs `matchMedia`/`ResizeObserver`; the axe helper disables the page-level `region` and (unrenderable) `color-contrast` rules for isolated-component checks.
- `PriceQtyForm`'s compact (non-`labeled`) variant carries an `aria-label` per input in addition to the visual placeholder (a placeholder is not an accessible name), so both variants pass axe.

## Shared modules (`src/`)

- `src/api.ts` — ALL fetch calls; pages never call `fetch` directly. `authedFetch` wraps authenticated requests: any 401 clears the stored token and throws `SessionExpiredError`; pages catch it and redirect to `/login` with that notice (via `useSessionRedirect`). Token lives in `localStorage`. `login()` special-cases 429: it surfaces the backend's rate-limit detail instead of the generic "Invalid credentials". `getMe()` / `updateProfile(updates)` / `changePassword(current, next)` back the Profile page (all authed; the update calls surface the backend's 400/409 `detail`). `changePassword` and `signOutOtherDevices()` both `setToken` the fresh JWT the backend returns after bumping `token_version`, so the current tab isn't logged out when other sessions are revoked. `resendVerification()` (authed) re-sends the email-verification link; `UserProfile.email_verified` drives the Profile badge. `deleteAccount()` calls `DELETE /auth/me` and clears the local token on success. `forgotPassword(email)` / `resetPassword(token, newPassword)` back the ResetPassword page, and `verifyEmail(token)` backs the `/verify-email` page (all three unauthed; `forgotPassword` returns the backend's generic message and only really fails on a 429). **Social sign-in:** `getOAuthProviders()` (unauthed, returns the backend's configured providers — `[]` on any hiccup so it never blocks the form) and `oauthLoginUrl(provider)` (the full-page `/auth/oauth/{provider}/start` URL a button links to, NOT a fetch — the browser follows the OAuth redirect chain itself) back the `SocialSignIn` buttons; `UserProfile` now also carries `has_password` (false for social-only accounts) and `oauth_providers` (the linked provider names). `getAdminStats()` (authed) backs the Admin page — a 404 throws `NotAdminError` (rendered as "Page not found"), typed as `AdminStats`; `UserProfile.is_admin` is the flag Profile keys its Admin link on. **Price-feature types/calls:** `PriceChange` (`{amount, percent, since}`, on `Card.priceChange` and `PortfolioCard.price_change`), `Card.refreshing` (backend is re-fetching a stale catalog price — CardDetail re-polls while set), `Card.estimate` (`{value, date}` — stored eBay-median for TCGPlayer-priceless cards, rendered muted on tiles), `Card.varietyOf` (the base-card id on a synthetic stamp/mark variety card), `PricePoint`, `CardHistory` (`{points, variants}` from `getCardHistory`), `EbayEstimate`; `getCardHistory(cardId, days?)` and `getEbayEstimate(cardId)` (both unauthenticated). `getCardPrice` reads its variant order from `PRICE_PREFERENCE` in `variants.ts` — keep it in sync with the backend's `extract_price`. Card-list endpoints return the paged envelope `CardPage` (`{data, page, pageSize, totalCount}`). `scanCard(blob)` POSTs a captured card image to `/scan` as multipart (**authed** — `/scan` is login-only, so it goes through `authedFetch`; 401 → `SessionExpiredError`; no `Content-Type` — the browser sets the boundary) and returns the same `CardPage` of nearest-match cards for the camera scanner; each returned `Card` also carries `matchScore` (CLIP cosine, only set by `/scan`). `reportScanFeedback(events)` (roadmap #10 accuracy telemetry) is **fire-and-forget** — it runs its own `fetch` (NOT `authedFetch`, so a failed/expired-token ping can never clear the session or throw) with `keepalive`, swallowing all errors; the Scan page calls it after a successful add (one `confirmed` event per card, `picked_rank` = the chosen candidate's index) or on an explicit miss (`searched_away`/`rescanned`). Typed `ScanFeedbackEvent`/`ScanOutcome`; the backend stores rows anonymously. `addCardBatch(items, portfolioId?)` (authed) POSTs `/portfolio/add-batch` for the scanner's batch mode **and the Portfolio CSV import** — an array of `{card_id, purchase_price|null, quantity, purchase_date?, grading?, grade?}` plus an optional target `portfolio_id` — and returns `BatchAddResult` (`{added, failed: [{card_id, reason}], message}`); `BatchAddItem.purchase_date` is optional and set only by CSV import (restores an imported lot's original date; omitted, the backend stamps now). **Named-portfolio calls:** `getPortfolios()`, `createPortfolio(name)`, `renamePortfolio(id, name)`, `deletePortfolio(id)` (typed `Portfolio` = `{id, name, is_default, created_at, card_count}`); `getPortfolio(portfolioId?)`, `getPortfolioHistory(portfolioId?)`, and `addCard(card_id, price, qty, portfolioId?, condition?)` all take an optional portfolio id (and `addCard` a `LotCondition` `{grading, grade}` — roadmap #7; `useAddCard.add`'s 6th arg threads it) — **omit `portfolioId` on `getPortfolio` for the account-wide list** (see `owned.ts`), pass it to scope. These are consumed through the `src/portfolios.ts` store. `getSetCompletion(portfolioId?)` (authed, same optional scoping — omit for account-wide) returns `SetCompletion[]` (`{set_id, set_name, series, release_date, printed_total, owned, total, logo, symbol}`) — per-set completion; the account-wide read is cached in `src/setCompletion.ts`. **Watchlist calls (authed):** `getWatchlist()` (typed `WatchlistItem` = `{id, card_id, card_name, target_price, direction, created_at, current_price, price_change, image_url, triggered}` — priced through the same pipeline as a `PortfolioCard`), `addToWatchlist(card_id, target_price|null, direction?)` (an **upsert** — the backend keys on (user, card)), `updateWatchlistItem(id, target_price|null, direction)`, `removeFromWatchlist(id)` — back the Watchlist page and the `WatchButton` on CardDetail.
- `src/hooks.ts` — `useAddCard`: the whole add-to-portfolio flow (token check → `/login` redirect, price/qty parsing, self-clearing status message — 3s success / 4s error, busy flag) shared by Search/CardDetail/Scan; `add(cardId, price, qty, portfolioId?, onSuccess?)` — the optional `portfolioId` (from a `PortfolioPicker`, defaulting to the active portfolio) is threaded into `addCard`. On success it calls `invalidateOwned()` (see `owned.ts`) and `invalidateSetCompletion()` (see `setCompletion.ts`) so the Search "Owned ×N" badges and the set-completion meters refresh after any add. `useSessionRedirect`: the single source of the "Your session expired — please log in again." redirect — every authed flow must use it so the notice stays in sync with `Login.tsx`.
- `src/owned.ts` — a module-level cache of `card_id -> total quantity held`, from one `getPortfolio()` call (no `portfolio_id` → **account-wide**, so "Owned ×N" means owned in any portfolio), so the Search grid can badge cards you already own without refetching on every mount. `getOwnedQty()` (empty when signed out; shares one in-flight request; cached across navigation) and `invalidateOwned()` (dropped after any add via `useAddCard`).
- `src/setCompletion.ts` — a module-level cache of the user's **account-wide** per-set completion (one `getSetCompletion()` call, no `portfolio_id`), so CardDetail can show "you own X/Y of this set" without refetching on every card view. Same shape as `owned.ts`: `getOwnedSetCompletion()` (empty `[]` when signed out; single-flight; cached across navigation) and `invalidateSetCompletion()` — dropped after any add via `useAddCard`, alongside `invalidateOwned()`. The Portfolio page reads its own portfolio-scoped completion directly (not this cache).
- `src/portfolios.ts` — the active-portfolio store (a `useSyncExternalStore` store like `accessibility.ts`, but hydrated from the backend): `usePortfolios()` gives `{portfolios, active, activeId, setActive, refresh, loaded}`, auto-hydrating on first use when signed in (single-flight, like `owned.ts`). The list comes from `getPortfolios()`; the active id persists to `localStorage` and is reconciled against the fetched list on refresh (a stale/other-account id falls back to the default portfolio). `clearPortfolios()` on logout/account-deletion. `refresh()` after create/rename/delete. Callers thread the active (or a picked) id into `getPortfolio`/`getPortfolioHistory`/`addCard`/`addCardBatch`.
- `src/accessibility.ts` — device-local display preferences (`reduceMotion`, `highContrast`, `underlineLinks`, `textSize`: `default`/`large`/`larger`), persisted to localStorage and mirrored onto `<html>` as `data-*` attributes that `index.css` styles off (reduce-motion also short-circuits Navbar's auto-hide and HeroSearch's typewriter, and the CSS honors OS `prefers-reduced-motion` too; text size is a `<html>` `zoom` since the app's sizes are px). Applied at import time so preferences take effect before first paint. `useAccessibility()` (a `useSyncExternalStore`-backed store) gives every consumer `{settings, update}` in sync without a synchronous effect setState. Never sent to the backend — there's no user-settings storage; they're intentionally per-browser.
- `src/format.ts` — `money()`: `$1,234.56` (thousands-separated via `toLocaleString`), or an em dash for missing values; `signedMoney()`: signed dollar amount with the sign **before** the `$` (`+$6.31` / `-$58.11` / `$0.00`), used by `GainLoss` and the portfolio/holding P&L figures.
- `src/portfolio.ts` — shared portfolio math for the Portfolio grid and the Holding route (`/portfolio/:cardId`), so both derive a card's quantity/cost/avg/value/P&L identically: `groupByCard` (lots → one `CardGroup` per **holding** = `holdingKey(card_id, grading, grade)`, roadmap #7 Option B — a raw and a graded copy of one card are separate groups; `CardGroup` carries `key`/`grading`/`grade`, so callers key metrics maps by `group.key`, NOT `card_id`), `groupMetrics` (qty, cost, avg, market, value, gain, gainPct, min/maxPaid, today's `dayChange` = per-unit change × qty, newest/oldest timestamps), and the `parseUTCDate`/`localISODate`/`lotISODate`/`formatLotDate`/`formatChartDate` date helpers (naive-UTC purchase dates are anchored with `Z` before formatting).
- `src/grading.ts` — shared condition/grade vocabulary + helpers (roadmap #7), pure and unit-tested. `GRADING_TYPES` (`Raw`/`PSA`/`BGS`/`CGC`/`SGC`/`Other` — keep in sync with backend `GRADING_TYPES`), `RAW_CONDITIONS`/`GRADE_OPTIONS` (the picker's per-type value lists), `DEFAULT_GRADING`/`DEFAULT_GRADE` (`Raw`/`Near Mint` — the add default, consistent with the raw market prefill), `isGraded` (mirrors the backend's `_is_graded`), `conditionLabel` ("PSA 10"), `holdingKey` (the Option B group key), `conditionKey` (the Holding route's `?g=` param, `''` = unset). Consumed by `GradingPicker`, `SlabbedCardImage`, `portfolio.ts`, `portfolioCsv.ts`.
- `src/portfolioCsv.ts` — portfolio CSV round-trip logic (pure, unit-tested like `format`/`portfolio`; no fetches). `toPortfolioCsv(cards)` serializes **one row per lot** (so a Mintly export re-imports exactly) with raw numeric values, RFC-4180 quoting, and a formula-injection guard on the `name` column. `parsePortfolioCsv(text)` reads a CSV into `BatchAddItem[]` — columns map by header name (case-insensitive; a headerless file falls back to positional `card_id, purchase_price, quantity, purchase_date`), `card_id` is required (missing-id rows are skipped and counted), a blank/invalid price → `null` (market), a blank/invalid quantity → `1`. Consumed by the `PortfolioCsv` component.
- `src/affiliate.ts` — outbound buy-link building (no fetches, so `api.ts`'s monopoly on network calls is untouched): `tcgplayerSearchUrl` (name+number product search) and `tcgplayerBuyLink` → `{href, affiliate}` — the card's stored `tcgplayer.url` else the search fallback, wrapped as `<VITE_TCGPLAYER_IMPACT_LINK>?u=<encoded dest>` ONLY when the env var is set and the destination is on tcgplayer.com (Impact deeplinks don't attribute other domains — upstream's `prices.pokemontcg.io` redirect stays a plain link, so with Impact live, commission accrues on TCGCSV-priced cards' product links and search fallbacks, not upstream-priced cards' redirects). `ebaySearchUrl`/`ebayBuyLink` build the buy box's eBay counterpart: an active-listings `ebay.com/sch/i.html` search keyed on the card's name + collector number — the `4/102` form when the number is plain digits and the set carries a `printedTotal`, the bare number for lettered numbers (`TG12`, `SWSH066`), the set name for numberless cards — with the EPN affiliate params (`campid` + the standard `mkcid`/`mkrid`/`siteid`/`mkevt`/`toolid` set, mirroring `ebay_prices._EPN_PARAMS` — keep them in sync) appended when `VITE_EBAY_EPN_CAMPAIGN_ID` is set. `affiliate: true` from either builder drives CardDetail's `rel="sponsored"` and its FTC disclosure line.
- `src/variants.ts` — shared variant vocabulary: `PRICE_PREFERENCE`, `variantLabel`/`variantShortLabel`, the fixed per-variant chart colors (`variantColor` — assigned by variant name, never position; colorblind-validated for the dark surface), `sortVariants`, `mergeHeadline` (backfills the headline series into the preferred variant's, since pre-variant history IS that variant).

## Styling

- **CSS Modules, co-located.** Each component and page has a `*.module.css` beside it holding its own styles (imported as `styles`, applied `className={styles.camelCase}`; `vite.config.ts` sets `css.modules.localsConvention: 'camelCase'`, so the CSS files keep kebab-case names while components read clean camelCase). Class names are hashed and scoped, so styles can't leak between components. `src/App.css` is now only the **global/shared** layer: the app shell (`.main`/`.page`/`.centered`), buttons, the shared filter/card-tile/add-form primitives, the **`.segmented` control** (pill track + cream selected item, `.on-card`/`.segmented-lg` modifiers — shared by the Portfolio filter row, the chart range toggles, and the Scan Single/Batch toggle), utilities (`.positive`/`.negative`/`.error`/`.prices-note`, plus **`.num`** = `font-variant-numeric: tabular-nums`, set on every money/percent/date figure), the legal-page styles, and the `day-change-*` chip (its direction classes are built with dynamic names, so the whole family stays global). `index.css` holds the design tokens (CSS variables) and reset — including the SF system stack (`--font-ui`/`--font-display`, the `:root` font shorthand uses `--font-ui`), the `--radius-lg`/`-md`/`-sm` scale, `--hairline` (quieter than `--border`), the `--warn*` amber family (`--warn`/`-bg`/`-border`/`-border-strong`, used by the Scan page's low-confidence UI), and a few decorative one-off grays (`--text-dim`/`--dot`/`--slash`/`--border-dashed`) used only for non-content dimming/separators. Rule of thumb: a class used by **one** component lives in its module; a class shared by **two or more** stays global. Overrides that cross the boundary use `:global()` — e.g. `Portfolio.module.css` styles the shared button as `.card-actions :global(.btn-outline)`.
- **Fluid/intrinsic layout, not breakpoints.** Grids reflow with `repeat(auto-fill|auto-fit, minmax(min(100%, clamp(…)), 1fr))`, and typography/spacing scale with `clamp()`. This handles any viewport — a folded phone (~280px) through iPad and tablet split-screen up to desktop — with no device-specific media query; the `min(100%, …)` inside each `minmax` is the overflow guard for very narrow screens. The single deliberate breakpoint is the navbar in `Navbar.module.css`. Wide data (the card-detail price table) sits in an `overflow-x:auto` box; flex-wrapped inputs carry `min-width: 0` so they shrink rather than overflow. Theme is dark/minimal with a framed layout: a neutral near-black outer frame (`--frame`) the translucent navbar merges into, all page content on one big rounded graphite panel (`.main`, `--bg`), cream (`--cream`) primary buttons with ink text, mint accent — keep new UI inside this palette (`--bg-card`, `--border`, `--text`, `--text-h`, `--accent`, `--positive`, `--negative`, `--ink`).

## Conventions

- New React components go in `src/components/`, one file per component — don't define reusable components inline in page files. Pages under `src/pages/` are route entries only; if a piece of UI is (or is about to be) used by more than one page, extract it to `components/` first.
- Styling is **CSS Modules** (see Styling above). Style a global class from inside a module with `:global(.btn-outline)`; mixing a global string with a module class is fine (`` className={`filter-select ${styles.filterNumber}`} ``).
- Authenticated frontend calls go through `authedFetch` in `api.ts`. Pages catch `SessionExpiredError` and redirect to `/login` with a notice in router state — new authed flows must do the same, via `useSessionRedirect` from `hooks.ts` (don't hand-roll the redirect/notice). One deliberate exception: the Admin page renders the 404 view instead — a session-expired notice there would reveal the hidden page exists.
- Mirror user-facing backend validation rules client-side for instant feedback, with identical messages. Card-list endpoints return `{data, page, pageSize, totalCount}` (typed `CardPage`).
- No native `confirm()`/`alert()` dialogs: errors show as inline `StatusMessage` lines (self-clearing, 4s) and destructive actions use inline two-step confirm buttons (see `Portfolio.tsx`); account deletion adds a typed-"DELETE" gate (`DeleteAccount.tsx`) since it's irreversible.
- Accessibility/display preferences are **device-local, not account data** (see `accessibility.ts` above) — apply them as `<html>` `data-*` attributes styled from `index.css`, don't persist them server-side. The controls are the shared `AccessibilitySettings` component, hosted both on Profile (signed in) and the public `/accessibility` page.
- **Accessibility baseline — target WCAG 2.1 AA.** The app shell has a "Skip to main content" link (`.skip-link` → `<main id="main-content" tabIndex={-1}>` in `App.tsx`), unique landmark labels (`<nav aria-label="Primary">` Navbar, `aria-label="Footer">` footer nav), and a global `:focus-visible` accent ring in `index.css`; `/accessibility` carries the conformance statement + feedback contact. **Contrast:** real content must clear 4.5:1 — use `--text` for readable copy, never `--text-dim` (~3.3:1), which is only for large figures (≥18px → 3:1 ok), disabled controls (exempt), placeholders, and decoration. Inline prose links get an underline (`.legal-page p a`) so they don't rely on color alone (1.4.1). Verify with the token contrast math and an axe run over the real pages (see Tests).
- Structured data must describe visible page content only. The per-card `Product` markup (`cardJsonLd` in `CardDetail.tsx`) carries **no `offers` block** — it emits name/image/description/sku/brand only; the prices shown are third-party market/estimate figures, not Mintly listings. The static `<title>` in `index.html` and `DEFAULT_TITLE` in `CardDetail.tsx` must stay identical (CardDetail restores it on unmount).

## Gotchas

- eslint react-hooks v7 is strict: no synchronous `setState` inside `useEffect` bodies — set state in promise callbacks, or defer via `setTimeout` (see the debounce effect in `Search.tsx`), or remount the component with a `key` so its state re-initializes (see `PriceHistoryChart`).
- Always verify with `npm run build` (not just eslint) — the strict tsconfig catches things lint doesn't, e.g. recharts callback param types.
- CSS Modules typos are silent: a mis-keyed `styles.foo` is `undefined`, so the element renders unstyled with no TS or build error. After any styling/className change, verify the UI in the browser — a green `npm run build` is not enough.
