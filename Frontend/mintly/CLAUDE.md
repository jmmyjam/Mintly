# Frontend — `Frontend/mintly/`

React 19 + TypeScript + Vite + React Router 7 + Recharts. Global rules live in the repo-root `CLAUDE.md`. Page/component detail loads automatically when you work in it: `src/pages/CLAUDE.md`, `src/components/CLAUDE.md`.

## Commands

Run from `Frontend/mintly/` — NOT the repo root:
```bash
npm run dev        # Vite dev server on :5173
npm run build      # tsc + vite build — use this to verify changes compile
npx eslint src/    # lint
```
The API base URL comes from `VITE_API_BASE` (baked in at build; unset defaults to `http://localhost:8000`). The frontend has no tests yet.

## Shared modules (`src/`)

- `src/api.ts` — ALL fetch calls; pages never call `fetch` directly. `authedFetch` wraps authenticated requests: any 401 clears the stored token and throws `SessionExpiredError`; pages catch it and redirect to `/login` with that notice (via `useSessionRedirect`). Token lives in `localStorage`. `login()` special-cases 429: it surfaces the backend's rate-limit detail instead of the generic "Invalid credentials". `getMe()` / `updateProfile(updates)` / `changePassword(current, next)` back the Profile page (all authed; the update calls surface the backend's 400/409 `detail`). `deleteAccount()` calls `DELETE /auth/me` and clears the local token on success. `forgotPassword(email)` / `resetPassword(token, newPassword)` back the ResetPassword page (both unauthed; `forgotPassword` returns the backend's generic message and only really fails on a 429). `getAdminStats()` (authed) backs the Admin page — a 404 throws `NotAdminError` (rendered as "Page not found"), typed as `AdminStats`; `UserProfile.is_admin` is the flag Profile keys its Admin link on. **Price-feature types/calls:** `PriceChange` (`{amount, percent, since}`, on `Card.priceChange` and `PortfolioCard.price_change`), `Card.refreshing` (backend is re-fetching a stale catalog price — CardDetail re-polls while set), `Card.estimate` (`{value, date}` — stored eBay-median for TCGPlayer-priceless cards, rendered muted on tiles), `Card.varietyOf` (the base-card id on a synthetic stamp/mark variety card), `PricePoint`, `CardHistory` (`{points, variants}` from `getCardHistory`), `EbayEstimate`; `getCardHistory(cardId, days?)` and `getEbayEstimate(cardId)` (both unauthenticated). `getCardPrice` reads its variant order from `PRICE_PREFERENCE` in `variants.ts` — keep it in sync with the backend's `extract_price`. Card-list endpoints return the paged envelope `CardPage` (`{data, page, pageSize, totalCount}`).
- `src/hooks.ts` — `useAddCard`: the whole add-to-portfolio flow (token check → `/login` redirect, price/qty parsing, self-clearing status message — 3s success / 4s error, busy flag) shared by Search and CardDetail; `useSessionRedirect`: the single source of the "Your session expired — please log in again." redirect — every authed flow must use it so the notice stays in sync with `Login.tsx`.
- `src/accessibility.ts` — device-local display preferences (`reduceMotion`, `highContrast`, `underlineLinks`, `textSize`: `default`/`large`/`larger`), persisted to localStorage and mirrored onto `<html>` as `data-*` attributes that `index.css` styles off (reduce-motion also short-circuits Navbar's auto-hide and HeroSearch's typewriter, and the CSS honors OS `prefers-reduced-motion` too; text size is a `<html>` `zoom` since the app's sizes are px). Applied at import time so preferences take effect before first paint. `useAccessibility()` (a `useSyncExternalStore`-backed store) gives every consumer `{settings, update}` in sync without a synchronous effect setState. Never sent to the backend — there's no user-settings storage; they're intentionally per-browser.
- `src/format.ts` — `money()`: `$12.34`, or an em dash for missing values.
- `src/affiliate.ts` — outbound buy-link building (no fetches, so `api.ts`'s monopoly on network calls is untouched): `tcgplayerSearchUrl` (name+number product search) and `tcgplayerBuyLink` → `{href, affiliate}` — the card's stored `tcgplayer.url` else the search fallback, wrapped as `<VITE_TCGPLAYER_IMPACT_LINK>?u=<encoded dest>` ONLY when the env var is set and the destination is on tcgplayer.com (Impact deeplinks don't attribute other domains — upstream's `prices.pokemontcg.io` redirect stays a plain link, so with Impact live, commission accrues on TCGCSV-priced cards' product links and search fallbacks, not upstream-priced cards' redirects). `ebaySearchUrl`/`ebayBuyLink` build the buy box's eBay counterpart: an active-listings `ebay.com/sch/i.html` search keyed on the card's name + collector number — the `4/102` form when the number is plain digits and the set carries a `printedTotal`, the bare number for lettered numbers (`TG12`, `SWSH066`), the set name for numberless cards — with the EPN affiliate params (`campid` + the standard `mkcid`/`mkrid`/`siteid`/`mkevt`/`toolid` set, mirroring `ebay_prices._EPN_PARAMS` — keep them in sync) appended when `VITE_EBAY_EPN_CAMPAIGN_ID` is set. `affiliate: true` from either builder drives CardDetail's `rel="sponsored"` and its FTC disclosure line.
- `src/variants.ts` — shared variant vocabulary: `PRICE_PREFERENCE`, `variantLabel`/`variantShortLabel`, the fixed per-variant chart colors (`variantColor` — assigned by variant name, never position; colorblind-validated for the dark surface), `sortVariants`, `mergeHeadline` (backfills the headline series into the preferred variant's, since pre-variant history IS that variant).

## Styling

- **CSS Modules, co-located.** Each component and page has a `*.module.css` beside it holding its own styles (imported as `styles`, applied `className={styles.camelCase}`; `vite.config.ts` sets `css.modules.localsConvention: 'camelCase'`, so the CSS files keep kebab-case names while components read clean camelCase). Class names are hashed and scoped, so styles can't leak between components. `src/App.css` is now only the **global/shared** layer (~240 lines): the app shell (`.main`/`.page`/`.centered`), buttons, the shared filter/card-tile/add-form primitives, utilities (`.positive`/`.negative`/`.error`/`.prices-note`), the legal-page styles, and the `day-change-*` chip (its direction classes are built with dynamic names, so the whole family stays global). `index.css` holds the design tokens (CSS variables) and reset. Rule of thumb: a class used by **one** component lives in its module; a class shared by **two or more** stays global. Overrides that cross the boundary use `:global()` — e.g. `Portfolio.module.css` styles the shared button as `.card-actions :global(.btn-outline)`.
- **Fluid/intrinsic layout, not breakpoints.** Grids reflow with `repeat(auto-fill|auto-fit, minmax(min(100%, clamp(…)), 1fr))`, and typography/spacing scale with `clamp()`. This handles any viewport — a folded phone (~280px) through iPad and tablet split-screen up to desktop — with no device-specific media query; the `min(100%, …)` inside each `minmax` is the overflow guard for very narrow screens. The single deliberate breakpoint is the navbar in `Navbar.module.css`. Wide data (the card-detail price table) sits in an `overflow-x:auto` box; flex-wrapped inputs carry `min-width: 0` so they shrink rather than overflow. Theme is dark/minimal with a framed layout: a neutral near-black outer frame (`--frame`) the translucent navbar merges into, all page content on one big rounded graphite panel (`.main`, `--bg`), cream (`--cream`) primary buttons with ink text, mint accent — keep new UI inside this palette (`--bg-card`, `--border`, `--text`, `--text-h`, `--accent`, `--positive`, `--negative`, `--ink`).

## Conventions

- New React components go in `src/components/`, one file per component — don't define reusable components inline in page files. Pages under `src/pages/` are route entries only; if a piece of UI is (or is about to be) used by more than one page, extract it to `components/` first.
- Styling is **CSS Modules** (see Styling above). Style a global class from inside a module with `:global(.btn-outline)`; mixing a global string with a module class is fine (`` className={`filter-select ${styles.filterNumber}`} ``).
- Authenticated frontend calls go through `authedFetch` in `api.ts`. Pages catch `SessionExpiredError` and redirect to `/login` with a notice in router state — new authed flows must do the same, via `useSessionRedirect` from `hooks.ts` (don't hand-roll the redirect/notice). One deliberate exception: the Admin page renders the 404 view instead — a session-expired notice there would reveal the hidden page exists.
- Mirror user-facing backend validation rules client-side for instant feedback, with identical messages. Card-list endpoints return `{data, page, pageSize, totalCount}` (typed `CardPage`).
- No native `confirm()`/`alert()` dialogs: errors show as inline `StatusMessage` lines (self-clearing, 4s) and destructive actions use inline two-step confirm buttons (see `Portfolio.tsx`); account deletion adds a typed-"DELETE" gate (`DeleteAccount.tsx`) since it's irreversible.
- Accessibility/display preferences are **device-local, not account data** (see `accessibility.ts` above) — apply them as `<html>` `data-*` attributes styled from `index.css`, don't persist them server-side.
- Structured data must describe visible page content only. The per-card `Product` markup (`cardJsonLd` in `CardDetail.tsx`) carries **no `offers` block** — it emits name/image/description/sku/brand only; the prices shown are third-party market/estimate figures, not Mintly listings. The static `<title>` in `index.html` and `DEFAULT_TITLE` in `CardDetail.tsx` must stay identical (CardDetail restores it on unmount).

## Gotchas

- eslint react-hooks v7 is strict: no synchronous `setState` inside `useEffect` bodies — set state in promise callbacks, or defer via `setTimeout` (see the debounce effect in `Search.tsx`), or remount the component with a `key` so its state re-initializes (see `PriceHistoryChart`).
- Always verify with `npm run build` (not just eslint) — the strict tsconfig catches things lint doesn't, e.g. recharts callback param types.
- CSS Modules typos are silent: a mis-keyed `styles.foo` is `undefined`, so the element renders unstyled with no TS or build error. After any styling/className change, verify the UI in the browser — a green `npm run build` is not enough.
