# Backend scripts — `Backend/scripts/`

Standalone batch jobs (talk straight to the DB + upstream; the FastAPI app need not be running). Global rules: repo-root `CLAUDE.md`; backend-wide detail: `Backend/CLAUDE.md`. The daily job is scheduled via launchd on this Mac (see `Backend/CLAUDE.md` / HANDOFF "Daily snapshot job") and via server cron in production (HANDOFF "Production deployment").

```bash
venv/bin/python scripts/snapshot_all.py          # snapshot every card's price into history (daily job; --max-pages N to limit, --no-tcgcsv skips the TCGCSV price fill, --max-ebay N caps the eBay fill (0 skips), --ebay-pause S paces it, --no-archive skips the cold-storage backup, --no-alerts skips watchlist price alerts)
venv/bin/python scripts/archive_history.py       # price-history cold-storage backup by hand: back up old months now / --list / --restore YYYY-MM
venv/bin/python scripts/embed_catalog.py         # backfill CLIP image embeddings for the card scanner (--all recomputes, --limit N caps, --workers/--chunk tune throughput)
scripts/backup.sh                                # nightly backup: verified pg_dump + .archive/price-history copy + rotation + optional off-server rsync (BACKUP_REMOTE); on this Mac needs PG_BIN=/opt/homebrew/opt/postgresql@15/bin
```

- `Backend/scripts/snapshot_all.py` — standalone daily job that records a price snapshot for **every** card, so history is gap-free instead of only covering browsed/held cards. Pages the full card list (`GET /cards` with a `select=` of the full frontend field set, ~20k cards / ~82 pages of 250), extracts each price, and calls `record_snapshots` in chunks. Upstream flakes with transient 404s/timeouts, so each page is retried up to 3× with backoff; pages that still fail are remembered and **re-tried in up to 3 end-of-run sweeps** (cool-downs doubling 30s → 60s → 120s — a flake burst that outlives one pause rarely outlives three minutes). A page failing every sweep is **skipped, not fatal** — the crawl finishes the other ~80 and flags itself incomplete (missing cards get caught next run). **Page 1 is special**: it carries `totalCount`, so the crawl can't even start without it — a transient upstream 500 / DNS blip there used to abort the ENTIRE day's snapshot (observed ~5 of the first 44 days: `page 1 attempt 3/3: HTTP 500` → `fetched no prices — leaving history untouched`). So page 1 now gets its own **long, widening retry schedule** (`_PAGE1_RETRY_PASSES`/`_PAGE1_RETRY_PAUSE` — waits of 5/10/20/40 min, a ~75-min recovery window, deliberately spaced far apart so a network issue isn't just re-hit seconds later) before the run gives up; only an outage spanning that whole window returns an empty crawl. Cards with **no TCGPlayer price** (~1.6k of the catalog: the newest sets plus old oddballs like e-Card holos) then get fallbacks, in accuracy order. **First `tcgcsv_fill`** (`--no-tcgcsv` skips): real, variant-separated TCGplayer prices from the TCGCSV mirror via `app/services/tcgcsv.py`, one group fetch per set, **injected into the card dicts as a normal `tcgplayer.prices` block** and snapshotted — this runs BEFORE the catalog upsert (so the enriched dicts are what the catalog stores, and the app renders these cards as ordinarily TCGplayer-priced, variant tiles and all) and BEFORE the eBay pass (which only sees the remainder); unmatched sets are listed in the log (fix via `_GROUP_OVERRIDES`); matching is name-aware (`pick_candidate`). Injection goes through `_apply_tcgcsv_block`, which marks the block `tcgplayer.priceSource = "tcgcsv"` — stopping the request-path 6h refresh from overwriting it with upstream's figure — and adds a direct `tcgplayer.url = tcgplayer.com/product/{productId}` buy link when the card has none (an existing url, upstream's own `prices.pokemontcg.io` redirect, is never overwritten). **Then `price_sanity_check`**: every card upstream DID price is cross-checked against the same TCGCSV mirror (all groups fetched, adding ~a minute); where the two headline prices diverge ≥3× on a name-and-number-matched product (`_SANITY_RATIO`; the name match is required — overriding a real price on a number-only match could price the wrong card), upstream's block is mapping the wrong product (observed July 23, 2026: swshp-SWSH066 served at the [Staff] promo's $580.92 vs the regular card's $98.49) or holding a junk figure ($19.99 for a ~$4k Shining Charizard), and TCGplayer's own number wins — the block is replaced (marked `priceSource`), `crawl.prices` corrected, and the day's snapshot re-recorded in place. **Then `image_fill`**: every crawled card's `images.small` URL is HEAD-checked (8 concurrent workers — but only URLs no run has verified before: a 200 stamps `verified` into the images block, which the catalog upsert and the request-path refresh carry forward, so each URL costs one check ever). Where the check 404s — `images.pokemontcg.io` answers a missing card image with a 404 whose **body is a generic card-back PNG** that browsers render as if it were the artwork (every card of the 2014/15/17/18 McDonald's sets) — the whole images block is replaced with the TCGplayer product scan (`product_images`, marked `source: "tcgplayer"`). Substituted cards fail the verified test next run and are re-checked, so upstream later adding a real scan heals back automatically; a 404 with no TCGplayer image leaves upstream's URLs in place (the frontend's `CardImage` detects the card-back and shows its placeholder). Skipped by `--no-tcgcsv`. After those passes, `record_variant_snapshots` runs over every crawled card (post-fill, so injected variant blocks get series too). Then the catalog upsert: every crawled card into `card_catalog` (best-effort — a catalog failure never costs the day's snapshots), **authoritative** (`keep_stored_prices=False`) whenever the TCGCSV fill ran — so a card still without a prices block has no priceable source left and its stored block clears instead of fossilizing a retracted price — with a complete, un-truncated run stamping the `last_full_sync` marker that lets the app's list endpoints trust the catalog (`--max-pages` smoke runs and crawls with dropped pages upsert but never stamp). **Then `variety_fill`** (skipped by `--no-tcgcsv`): for every crawled base card it forks each stamped/marked TCGplayer product sharing the card's number (`tcgcsv.variety_candidates` — a `[Staff]` stamp, `(Black Dot Error)`, `[W Stamped]`; finishes and number-collisions excluded) into a synthetic catalog card under id `<base_id>~v<productId>`, carrying its own name (`variety_name`), image (the product scan, or the base art when TCGCSV has none), price (TCGCSV, marked `priceSource: "tcgcsv"` with a product buy-link), and a `varietyOf` pointer to the base — then snapshots each (headline + per-variant rows) and upserts them authoritatively, so every stamped card is searched, charted, and held as its own card (nothing keys on more than the string `card_id`, so no schema change). **Then `ebay_fill`, the last resort**, over only the cards TCGCSV couldn't match: scrapes each card's eBay sold listings (via the `ebay_prices` pieces — `_estimate_one` distinguishes a failed fetch from a fetched-but-saleless page) and snapshots the sold **median** — newest sets first (`set.releaseDate` desc), skipping cards `recorded_today` says are already done, pausing `--ebay-pause` seconds between scrapes (default 3), capped at `--max-ebay` estimates per run (default 500; `0` skips the pass). Saleless results record nothing, stay gapped, and never stop the pass — only 5 **consecutive failed fetches** (the bot-block signature) end it early. **Then `recover_dropped`**, a final stage for **dropped pages** — pages pokemontcg.io couldn't serve even after every retry sweep, whose cards `_collect` never saw so they're in none of `crawl.cards/prices/unpriced` and neither fill above could reach them. It diffs the catalog against this run's crawled ids — any card the catalog holds that this run didn't crawl is, barring a rare upstream deletion, exactly a dropped page's card — presents those cards to the same `tcgcsv_fill` matcher, snapshots the TCGCSV price, and re-upserts the recovered cards. Gated to a full (non-`--max-pages`), already-synced run and skipped by `--no-tcgcsv`. **Then `watchlist_alerts.evaluate`** (skipped by `--no-alerts`): every card's price for today is now recorded, so it evaluates each user's watchlist alert thresholds against the fresh snapshots and emails whoever's card crossed (edge-triggered with a re-arm latch — see `app/services/watchlist_alerts.py`); best-effort, so a failure never costs the day's snapshots. The run finishes by calling `history_archive.archive` to back up complete months older than 30 days to cold-storage CSVs (`--no-archive` skips it; a failure is logged and never fails the run) — this **no longer thins the DB** (reverted Aug 20, 2026), so every daily row stays in `card_price_snapshot` and the CSVs are just a redundant backup. Idempotent (per-UTC-day dedupe; `record_snapshots` refreshes same-day rows in place, so a TCGCSV price recorded at 1pm replaces the morning's eBay median rather than duplicating it). No FastAPI app needed — it uses `app.database.SessionLocal` + its own upstream session. Keeps its own `_PAGE_SIZE = 250` deliberately — it's a retrying batch job where throughput beats per-request latency, unlike the user-facing 50/page in `app/routers/cards.py`. Scheduled by a launchd LaunchAgent (see `Backend/CLAUDE.md`).
- `Backend/scripts/backup.sh` — the nightly backup job for **non-Docker hosts** (plain bash; cron it like `10 3 * * * /path/to/Mintly/Backend/scripts/backup.sh >> /var/log/mintly-backup.log 2>&1`, after the day's snapshot job has archived — production's Docker deploy instead runs a server-local dockerized equivalent, see HANDOFF "Production deployment"). Two things are backed up: (1) a custom-format `pg_dump --no-owner` of `DATABASE_URL` into `BACKUP_DIR/db/mintly-YYYY-MM-DD.dump` — written to a temp file, checked readable with `pg_restore --list`, then renamed into place, one dump per UTC day (a same-day rerun overwrites); this now holds the **complete** price history since the DB keeps every daily row; (2) an rsync mirror of `Backend/.archive/price-history/` into `BACKUP_DIR/price-history/` — a redundant secondary copy of the old-month CSVs (deliberately no `--delete` — the source is append-only, so a bad/empty source can never erase already-backed-up months; missing dir = skipped, normal before the first archive). Local dumps rotate after `BACKUP_KEEP_DAYS` (default 14); if `BACKUP_REMOTE` is set (an rsync destination like `user@host:/backups/mintly`) the whole `BACKUP_DIR` is copied off-server, else the run **warns** — a backup on the DB's own disk doesn't survive the disk. Config resolves environment-first, then plain `KEY=value` lines in `Backend/.env` (`BACKUP_DIR` default `~/backups/mintly`; `PG_BIN` prepends a dir to PATH — this dev Mac needs `PG_BIN=/opt/homebrew/opt/postgresql@15/bin`, matching the running Homebrew postgresql@15). `DATABASE_URL` is never echoed. Restore: `pg_restore --clean --if-exists --no-owner -d "$DATABASE_URL" db/mintly-YYYY-MM-DD.dump`, then copy the archived CSVs back into `Backend/.archive/price-history/`.
- `Backend/scripts/archive_history.py` — manual CLI for the `app/services/history_archive.py` cold-storage **backup**: bare = back up old months now, `--list`, `--restore YYYY-MM` (loads a month's CSV rows back for a DB that lost them). The daily job calls `history_archive.archive` automatically at the end of its run; it no longer thins the DB.
- `Backend/scripts/embed_catalog.py` — backfills the CLIP image embeddings the camera scanner matches against (`app/services/card_embed.py`). For each `card_catalog` row missing an `embedding` (or all, with `--all`) it downloads the artwork (`data.images.large`, `small` fallback), **skips pokemontcg.io's 404 card-back PNG by status code** (a 404 still returns a card-back image), embeds it, and stores the float32 blob — concurrent downloads (`--workers`, 8 image workers like `image_fill`), batched encode + commit (`--chunk`), `--limit N` to cap. No FastAPI app needed (`SessionLocal` + its own session). **Not a daily job** — embeddings only change when a card's image does, so run it after a crawl or weekly. In production it runs in the api container (which has the model baked in): `docker compose exec -T api python scripts/embed_catalog.py`. `card_catalog.upsert_cards` never writes the `embedding` column, so the daily crawl leaves backfilled vectors intact; the api caches the embedding matrix (6h TTL), so **restart the api after the first backfill** to load it (`docker compose restart api`); later incremental runs appear within the TTL or on restart.
