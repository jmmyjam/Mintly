# Backend services — `Backend/app/services/`

Service/helper modules behind the routers. Global rules: repo-root `CLAUDE.md`; backend-wide commands, data model, conventions, gotchas: `Backend/CLAUDE.md`; the routers that call these: `Backend/app/routers/CLAUDE.md`.

- `Backend/app/services/card_catalog.py` — the local card catalog over `card_catalog`: `upsert_cards` (insert-or-update from upstream card dicts, stripped to the frontend field set `_KEEP` — mirrors the router's `_CARD_FIELDS`, plus `varietyOf` (the base-card id carried on synthetic variety rows; real upstream cards never have it) — and stamped `price_updated_at`; with `keep_stored_prices=True`, the request-path default, a stored non-empty `tcgplayer.prices` survives both an incoming EMPTY block — pokemontcg.io serves newest-set cards priceless for months, and the 6h background refresh / proxy-fallback upserts must not wipe the daily job's TCGCSV-filled prices — and, when the stored block is marked `tcgplayer.priceSource == "tcgcsv"`, an incoming upstream figure too, since that mark means the daily job judged upstream's price wrong for this card (the WHOLE stored block is kept either way — a job-injected `tcgplayer.url` product link rides along, so buy links survive refreshes); the fresh `price_updated_at` still stops the refresh loop either way. The daily crawl passes `keep_stored_prices=False`: it re-arbitrates every card's price source with fresh data, and its verdict lands verbatim — including clearing the stored block of a card no source prices any more, which would otherwise fossilize a retracted price forever. The flag also guards the `images` block the daily job arbitrates: a stored `images.source: "tcgplayer"` substitution — the job swapped dead upstream image URLs for the TCGplayer product scan — survives request-path refreshes (upstream still serves the dead URLs it replaced), and an unchanged upstream URL keeps its `images.verified` stamp so the next crawl doesn't HEAD-check it again; the crawl's authoritative upsert re-arbitrates both), `search` (paged `{data, page, pageSize, totalCount}` envelope plus the page's stale card ids; name = escaped ILIKE substring, number exact, and set/rarity/type accept a single value **or a list** — a list ORs within that facet (`IN` for set/rarity, an OR of `|Fire|`-delimited `types` LIKEs for type) while different facets still AND together), `get_card`/`get_cards` (single or batched primary-key fetch)/`card_payload` (payloads are copies so `priceChange` annotation never bleeds into the stored JSON), `set_count`, `price_is_stale` (`PRICE_TTL` 6h), and `is_synced`/`mark_full_sync` (the `catalog_meta` marker). List callers must gate on `is_synced`; single-row reads are always safe. The portfolio router reads `get_cards` too, to price cards pokemontcg.io returns unpriced.
- `Backend/app/services/price_history.py` — the shared snapshot layer over `card_price_snapshot`: `extract_price` (variant preference order), `variant_prices` (every priced variant of a card, market→mid — the same rule per variant), `recorded_today` (card ids that already have a headline snapshot this UTC day — `record_snapshots` dedupes through it, and the snapshot job checks it before spending an eBay scrape), `record_snapshots` (≤1 row per card per variant per UTC day, `variant=""` — the headline series — by default; a same-day re-record refreshes that row's price to the latest value seen rather than freezing at the first read, so the day's point keeps step with the current market price), `record_variant_snapshots` (one row per named variant, only for cards with 2+ priced variants — a lone variant IS the headline, and duplicating it would double the table for most of the catalog), `previous_prices` (each card's most recent snapshot strictly before today), `latest_prices` (most recent snapshot, today included), `price_change`, `change_baselines` (the comparison point for the daily-change chip: normally the most recent prior-day snapshot — but a day's row is refreshed in place to the last price seen, so right after the UTC rollover yesterday's close equals the current price and every chip would read $0.00 until the next crawl lands; when close == current the baseline steps one day further back, `since` carrying the older date, so the chip keeps showing the most recent real move), `annotate_price_changes` (records today — headline and variants — + attaches `priceChange` vs each card's `change_baselines` baseline to a list of card dicts, in place), `attach_estimates` (attaches `estimate` — the latest snapshot — plus a `priceChange` measured against the snapshot before that card's latest one, to cards with no TCGPlayer price, so tiles show the daily job's eBay median with the same daily-change chip as priced cards; `previous_prices` takes an optional `before` cutoff for exactly this), `card_history` (headline daily points for one card over a day window), and `card_variant_history` (the same, per named variant — `{}` for most cards). Every read helper filters to `variant == ""`; any new query against the snapshot table must do the same or variant rows pollute it (see `/portfolio/history`). Because the cards router annotates every browsed card, snapshots accumulate for anything users search or view — not just portfolio holdings.
- `Backend/app/services/tcgcsv.py` — real TCGplayer prices from [TCGCSV](https://tcgcsv.com), a free nightly mirror of TCGplayer's catalog + price files (refreshed daily at 20:00 UTC), used by the snapshot job to price the cards pokemontcg.io returns with an empty `tcgplayer.prices` block (it lags on brand-new sets). `group_id_for_set(set_name, set_id)` matches a pokemontcg.io set to a TCGplayer "group" by normalized name (their names carry a `"ME05: "`-style code prefix that's stripped; accents folded, so "Pokémon GO" matches "Pokemon GO"; `_GROUP_OVERRIDES`, keyed by pokemontcg.io set id, wins for stubborn mismatches — it covers the base sets whose TCGplayer names add "Base Set", the HS/promo/McDonald's sets, and both EX Trainer Kits — add entries as unmatched sets appear in the job log; only "Pokémon Futsal Collection" has no TCGplayer group at all). `candidates_for_group(group_id)` joins the group's products (card number from the `extendedData` `"Number"` entry; sealed products have none and are skipped — important, since a Booster Box carries real "Normal" prices) with its price rows, keyed by normalized number (`norm_number`: part before `/`, leading zeros stripped, case-folded — `"001/084"` → `"1"`, `"TG12/TG30"` → `"tg12"`), `subTypeName` mapped to the pokemontcg.io variant keys (`Normal`→`normal`, `Reverse Holofoil`→`reverseHolofoil`, …), rows with neither `marketPrice` nor `midPrice` dropped — one entry PER PRODUCT, since TCGplayer sells several products under one number ([Staff] prerelease stamps beside the regular promo; different cards sharing a number in merged groups like the EX Trainer Kit half-decks and WoTC promos). `pick_candidate(candidates, card_name, require_name=False)` chooses among them: candidates whose product name (before the " - <number>" tail) matches the card's name, then the ones without a bracketed qualifier (a [Staff] stamp is a different, rarer physical card), then the shortest name — deterministic, so the plain version always wins; `require_name=True` (the sanity check's mode) returns None instead of settling for a number-only match. It returns the whole product entry — name, `prices`, `image` (each candidate carries the products file's `imageUrl`, the TCGplayer product scan), and `productId` (the TCGplayer product id, which the snapshot job turns into `tcgplayer.com/product/{id}` buy links) — and `pick_product` is its prices-only view, so prices, images, and links always come from the same chosen product. **Card varieties:** `matching_candidates(candidates, card_name)` is the shared name filter — a product name reduced to its bare card name (the ` - <number>` tail and any trailing `[..]`/`(..)` qualifier stripped, so "Charizard (Black Dot Error)" and "Kabuto [W Stamped]" still match "Charizard"/"Kabuto") — and `variety_candidates(candidates, card_name)` returns the stamp/mark varieties that fork into their own cards: same-name products, minus the `pick_candidate` base, that carry a stamp/mark qualifier the base lacks (a `[Staff]` stamp, `[W Stamped]`, `(Black Dot Error)`); finishes never appear here (they're sub-types of ONE product, so one candidate) and a bare `(8)` collector-number disambiguator isn't a qualifier, so holo vs non-holo is never split. `variety_name(product_name)` cleans the display name (` - <number>` tail off, qualifier kept), and `variety_id`/`is_variety_id`/`base_of` mint and parse the synthetic `<base_id>~v<productId>` id (`~v` never occurs in a real pokemontcg.io id). `product_images(candidate)` shapes that scan into a pokemontcg.io-style images block for the snapshot job's image check: `small` = the listed `_200w.jpg` rendition, `large` = the `_in_1000x1000.jpg` suffix swap (asks the CDN for its largest — old promo products only have ~200px scans, which the CDN then serves), marked `source: "tcgplayer"`. `prices_for_group(group_id)` keeps the flat {number: variants} view with duplicates resolved to the base product; `card_prices(set_id, set_name, number, card_name=None)` is the one-card convenience — pass the name whenever it's known. Returned dicts are `tcgplayer.prices`-shaped, so `extract_price` and the frontend consume them unchanged. Groups list and per-group joins are memoized per process (the job is one process per day); failures aren't cached, so a later call can retry. Best-effort throughout — any fetch/parse failure returns empty/`None`, never raises. tcgcsv.com answers 401 to the default python-requests user agent — the module session sends an identifying `Mintly/1.0` UA. Batch-only by design: nothing on the request path calls it (the daily job's `tcgcsv_fill`/`variety_fill`/`price_sanity_check` do).
- `Backend/app/services/ebay_prices.py` — recent-eBay-sold price estimate for cards TCGPlayer can't price (since the TCGCSV fill, the daily job only sends it cards TCGCSV couldn't match; CardDetail's live estimate for a not-yet-crawled card is unchanged). `estimate(name, number, set_name)` builds a keyword query (`"<name> <number> -psa -bgs -cgc"`), fetches the completed-and-sold search page, parses it, and summarizes; results cached 12h (`_cache`). `_fetch_sold_html` seeds cookies from the eBay homepage then requests the search with a Referer, retrying once if it gets the bot-challenge page (`_looks_blocked`: the block page is a tiny "Error Page | eBay", a real page is ~1MB+). `parse_sold` walks `.su-card-container` tiles (BeautifulSoup + html.parser), reads the title from the image `alt`, the date from the "Sold <date>" caption, and the price *after* that caption (a leading price would be shipping/a range low), and drops graded/lots/proxies by title. `summarize` takes the most recent 25 sales, trims comps outside [0.35×, 3×] the median, and returns median/average/low/high/count/date-range/`source_url`/sample. Every failure path returns `count:0` — never raises. When the optional `EBAY_EPN_CAMPAIGN_ID` env var is set (read at import, mailer-style), `search_url` appends eBay Partner Network affiliate params to every `source_url` (`campid` plus the standard `mkcid`/`mkrid=711-53200-19255-0`/`siteid`/`mkevt`/`toolid` set for US ebay.com) — the frontend marks those links `rel="sponsored"`; unset leaves URLs untagged. The `/cards/{id}/ebay-price` endpoint also refreshes today's price snapshot to the scraped median (only for cards TCGPlayer can't price), so an eBay card's history point stays in step with the estimate CardDetail shows. (The eBay-scraping fragility gotcha is in `Backend/CLAUDE.md`.)
- `Backend/app/services/rate_limit.py` — per-IP sliding-window rate limiting as a FastAPI dependency. `rate_limit(scope, times, seconds, what=...)` returns a dependency for a route or a router's `dependencies=[]`; same-name scopes share one budget (the cards, portfolio, sitemap, and admin routers all register `"api"` at 120 req/min, so one client draws from a single allowance across them), and re-registering a scope with different numbers raises at import. Over-limit requests get a 429 with a `Retry-After` header and a "Too many … — try again in about Ns" detail; 429s pass back through CORSMiddleware, so browsers can read them. State is in-memory and per-process like the app's other caches (`reset()` clears it — conftest does this between tests; a multi-worker deploy multiplies every budget by the worker count). The client key is `request.client.host`; setting `RATE_LIMIT_TRUST_FORWARDED=1` keys on the first `X-Forwarded-For` hop instead — required behind a reverse proxy, dangerous without one (the header is client-controlled). Live scopes: `login` 10/5min, `register` 10/h, `password` 10/5min (change + reset share it), `forgot` 5/h, `api` 120/min, `ebay` 60/h, `scan` 60/min (the camera scanner's compute-heavy image match).
- `Backend/app/services/mailer.py` — outbound email over plain stdlib SMTP (`smtplib` + `EmailMessage`, no mail library), configured entirely by env: `SMTP_HOST`/`SMTP_PORT` (587 = STARTTLS, 465 = implicit TLS)/`SMTP_USER`/`SMTP_PASSWORD`/`MAIL_FROM` (defaults to `SMTP_USER`). `send_email(to, subject, body, html=None)` sends plain text, or multipart/alternative when `html` is given — the reset email passes a styled HTML version (`reset_email_html` in `app/routers/auth.py`) while the text part stays the fallback every client and spam filter can read. With no `SMTP_HOST` set (`is_configured()` false), `send_email` prints the text message to the console instead — so the reset flow works offline (the link lands in the uvicorn output) and tests never touch a network. On a real send failure it *raises*; the forgot-password route catches so its response can't leak whether a send happened. Production sends through **Resend**'s SMTP endpoint (`smtp.resend.com`, user `resend`, `MAIL_FROM="Mintly <noreply@mintlytcg.com>"` — see HANDOFF "Production deployment"; a `.env`-only config, no code change to swap providers). Never point production at Gmail SMTP: authenticated `smtp.gmail.com` submission stamps the submitting machine's IP into a `Received:` header, and anyone can trigger a reset email to their own inbox — leaking the home IP the Cloudflare Tunnel exists to hide.
- `Backend/app/services/admin_access.py` — who counts as an admin: the `ADMIN_EMAILS` env var (comma-separated account emails, case-insensitive, read at import like the mailer's config; tests monkeypatch the parsed `_ADMIN_EMAILS` set). Unset — the default — means no admins, so the feature is invisible until configured. Admin is configuration, not schema: no column, no migration; list only addresses that already belong to your own registered account (registration doesn't verify email ownership, so a listed-but-unregistered address could be claimed by anyone). `is_admin(user)` gates `admin.py`'s `GET /admin/stats` (non-admins get a plain 404) and is also read by `user_info` in auth.py, which is how `/auth/me` carries the `is_admin` flag the frontend keys the Profile→Admin link on.
- `Backend/app/services/history_archive.py` — cold storage that keeps `card_price_snapshot` from growing ~1.1GB/year, structured like stock-market data: the DB holds daily rows for the recent window plus one "monthly close" per card+variant per older month; the full old dailies live on disk. `compact(db)` finds complete months that ended more than `DAILY_WINDOW_DAYS` (30) ago, exports each to one gzipped CSV (`.archive/price-history/YYYY-MM.csv.gz`, ~3–6MB/month, columns card_id/variant/snapshot_date/price; `PRICE_ARCHIVE_DIR` env overrides the dir, tests point it at a temp dir) via atomic tmp+rename, then deletes the month's rows **except each card+variant's last** (the close — kept per variant so variant charts get monthly closes too). Ordering is strict: the file must exist on disk before any row is deleted, an existing file is never rewritten, and re-compacting an already-thinned month is a silent no-op. `restore_month(db, "YYYY-MM")` loads a month's archived rows back, skipping ones already present (archives written before the variant column restore as headline rows). Run automatically at the end of the daily snapshot job; `scripts/archive_history.py` is the manual CLI (bare = compact now, `--list`, `--restore YYYY-MM`).
- `Backend/app/services/card_embed.py` — CLIP image embeddings behind the camera scanner (`routers/scan.py`): `embed_pil`/`embed_pils` (sentence-transformers `clip-ViT-B-32`, CPU, lazily loaded — the heavy torch import is deferred so importing the module, e.g. in tests that monkeypatch it, stays cheap; 512-d L2-normalised float32 vectors), `embed_query` (an uploaded image **and** its horizontal mirror, so front-camera mirroring can't break the match), `catalog_matrix` (lazily loads + caches every stored `card_catalog.embedding` into an in-memory `(ids, matrix)` — 6h TTL like the app's other caches; `reset_cache()` clears it), and `nearest` (brute-force cosine `matrix @ query`, top-k via `argpartition` — sub-ms at ~20k cards, so no pgvector). Embeddings are backfilled by `scripts/embed_catalog.py`; the model is baked into the api image at build (`HF_HOME=/opt/models`), so scanning needs no per-request download.
