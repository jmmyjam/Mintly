# CLAUDE.md

Mintly — Pokemon TCG portfolio tracker. FastAPI + PostgreSQL backend, React 19 + TypeScript + Vite frontend. External data from the Pokemon TCG API (pokemontcg.io); prices via TCGPlayer fields in its responses. Production runs at **https://mintlytcg.com** — Docker Compose on the home server `pikachuserver` behind a Cloudflare Tunnel (see HANDOFF "Production deployment"); this Mac is the dev machine.

Start every chat message to the user with their name, Jimmy.

Full architecture, endpoint reference, and known behaviors: @HANDOFF.md

## Commands

Backend (run from `Backend/`, uses `venv/`):
```bash
venv/bin/uvicorn app.main:app --reload   # dev server on :8000, docs at /docs
venv/bin/python -m py_compile <file>.py  # quick syntax check
venv/bin/alembic upgrade head            # apply DB migrations
venv/bin/alembic revision --autogenerate -m "..."  # new migration after model changes
venv/bin/pytest tests/ -q                # run backend tests (offline: sqlite + fake upstream)
venv/bin/python scripts/snapshot_all.py          # snapshot every card's price into history (daily job; --max-pages N to limit, --no-tcgcsv skips the TCGCSV price fill, --max-ebay N caps the eBay fill (0 skips), --ebay-pause S paces it, --no-compact skips cold storage)
venv/bin/python scripts/archive_history.py       # price-history cold storage by hand: compact now / --list / --restore YYYY-MM
scripts/backup.sh                                # nightly backup: verified pg_dump + .archive/price-history copy + rotation + optional off-server rsync (BACKUP_REMOTE); on this Mac needs PG_BIN=/opt/homebrew/opt/postgresql@15/bin
```

A LaunchAgent (`~/Library/LaunchAgents/com.mintly.daily-snapshot.plist`) runs `scripts/snapshot_all.py` daily at 1pm local (just after TCGCSV's 20:00 UTC refresh, so the price fill reads same-day data), logging to `~/Library/Logs/mintly-daily-snapshot.log` — see HANDOFF for load/kickstart commands. It needs the Postgres in `DATABASE_URL` running. Because the repo lives under `~/Documents` (macOS TCC-protected), the agent invokes the framework Python directly and that binary must be granted **Full Disk Access** or every scheduled run fails with "Operation not permitted" (see HANDOFF "Daily snapshot job").

Frontend (run from `Frontend/mintly/` — NOT the repo root):
```bash
npm run dev        # Vite dev server on :5173
npm run build      # tsc + vite build — use this to verify changes compile
npx eslint src/    # lint
```

Backend tests live in `Backend/tests/` (auth, password reset, portfolio, card-search, price-history, history archive, eBay, TCGCSV, rate limiting, the health probe, the sitemap, the card catalog + the snapshot crawl). `conftest.py` swaps the DB for in-memory SQLite, resets the rate limiter between tests (every test request shares one client "IP"), pins `RATE_LIMIT_TRUST_FORWARDED=0` and `SMTP_HOST=""` (a dev `.env` may set either; the empty host keeps the mailer in print-to-console mode so tests can never send real email), and replaces `portfolio._session` with a fake upstream (`test_search.py`/`test_history.py`/`test_catalog.py` do the same for `cards.session`; `test_ebay.py` fakes `ebay_prices._fetch_sold_html`; `test_tcgcsv.py` fakes the `tcgcsv._fetch_*` helpers) — set env vars / fakes BEFORE importing app modules (they read config at import time). The frontend has no tests yet.

## Structure

- `Backend/app/main.py` — app assembly only: FastAPI app, CORS (`CORS_ORIGINS`), includes the auth/portfolio/cards/health/sitemap routers. This is the uvicorn target (`app.main:app`).
- `Backend/app/routers/health.py` — `GET /health`, the uptime-monitor probe: `SELECT 1` through the request DB session, `{"status": "ok"}` or 503. Unauthed and deliberately outside every rate-limit scope — a monitor polling every 5 min must never see a 429; keep it that way.
- `Backend/app/routers/sitemap.py` — `GET /sitemap.xml`: XML sitemap for crawlers — the public static pages plus `/card/{id}` for every `card_catalog` row, URLs built on `FRONTEND_BASE_URL`; shares the `"api"` rate-limit scope; a catalog failure still serves the static pages. `Frontend/mintly/public/robots.txt` points crawlers at it, and the Caddyfile routes `/sitemap.xml` to the api container so it serves from the site root.
- `Backend/app/routers/cards.py` — card/set endpoints + smart search, served **catalog-first**: once `card_catalog` is synced (`catalog_meta` marker, stamped only by a complete crawl), `/search`, `/cards`, `/sets/{id}/cards`, and `/cards/{id}` answer from the DB (newest-sets-first, name = case-insensitive substring). Zero-result queries, unknown cards, and incomplete sets (`set_count` < the sets list's `total`) fall back to the upstream proxy + response cache (`_cache`: fresh 6h, then stale-while-revalidate to 24h; mirrored to `Backend/.cache/cards`, `CARD_CACHE_DIR` overrides; `/sets/{id}` answered from the cached sets list) and results are upserted into the catalog. A viewed card whose stored price is >6h old (`card_catalog.PRICE_TTL`) is served instantly with `refreshing: true` while `_refresh_prices_in_background` re-fetches it (one batched `id:"…" OR …` call per stale page) — CardDetail re-polls until the flag clears. Every card-list/detail response still passes through `_with_price_changes` (snapshot + `priceChange`); also serves `/cards/{id}/history` and `/cards/{id}/ebay-price`. Upstream calls take `timeout=_TIMEOUT` (5s connect/60s read — keep it on any new call); the sets list is served stale at any age while a background thread refreshes — requests never block on a sets re-fetch (only a truly cold cache fetches synchronously).
- `Backend/app/services/card_catalog.py` — the local catalog over `card_catalog`: `upsert_cards` (strips card dicts to the frontend field set `_KEEP`; with `keep_stored_prices=True`, the request-path default, never replaces a stored non-empty `tcgplayer.prices` with an empty one — upstream lags behind TCGCSV-filled prices — nor a `priceSource: "tcgcsv"`-marked block with upstream's figure — that mark means the daily job judged upstream's price wrong; the crawl passes `False` so its arbitration lands verbatim, clearing blocks no source backs; the flag also guards the job-arbitrated `images` block — a stored `images.source: "tcgplayer"` substitution for dead upstream image URLs, and the `images.verified` stamp on an unchanged URL, both survive the refresh), `search` (paged envelope + stale-id list), `get_card`/`get_cards` (batch)/`card_payload`, `set_count`, `is_synced`/`mark_full_sync`. List endpoints must check `is_synced` before trusting it — a partial catalog confidently serving short pages is the failure mode to avoid; single-card reads are always safe.
- `Backend/app/routers/auth.py` — register/login (per-IP rate-limited: login 10/5min, register 10/h), JWT, `get_current_user` dependency, password rules; account self-service (all authed): `GET /auth/me` (profile: email/username/created_at/accepted_terms_at — never the hash), `PATCH /auth/me` (change email and/or username, per-field uniqueness vs other users), `POST /auth/me/password` (change password — verifies current, applies the same rules, rate-limited 10/5min), `DELETE /auth/me` self-service account deletion (removes the user + their `portfolio_cards` and `password_reset_tokens` — the shared per-card price snapshots aren't user-tied, so they stay). Password reset (both unauthed): `POST /auth/forgot-password` (rate-limited 5/h; response is identical whether or not the email exists — keep it that way, it's the anti-enumeration contract; emails a link to `FRONTEND_BASE_URL/reset-password?token=…` via `mailer`, one live token per user) and `POST /auth/reset-password` (consumes a single-use, 30-min, sha256-stored token; a weak new password 400s WITHOUT burning the token)
- `Backend/app/routers/portfolio.py` — portfolio CRUD, batched price fetching (`fetch_prices`, one upstream call per 100 cards, 15-min `_price_cache`; card image URLs ride along — never guess them from card ids, see HANDOFF), daily snapshots, history endpoint; each row carries `price_change` (daily) via `change_baselines`. Prices resolve from every source in accuracy order (`_fallback_prices`): live pokemontcg.io → the catalog's TCGCSV price → the latest eBay-median snapshot — so newest-set cards upstream returns unpriced still track a value (both `/portfolio` display and `/portfolio/add`'s auto-price). Upstream stays the source of truth where it has a price; the cache is seeded with the *resolved* value so a fallback price isn't masked by a cached upstream `None`.
- `Backend/app/services/price_history.py` — shared snapshot store: `extract_price`, `variant_prices` (every priced variant, market→mid), `recorded_today` (card ids already snapshotted this UTC day), `record_snapshots` (one row per card per variant per UTC day — variant `""` is the headline series every feature reads; refreshed in place to the latest price seen that day, so today's point tracks the current price, not the first read), `record_variant_snapshots` (per-variant rows, ONLY for cards with 2+ priced variants — a single variant IS the headline, duplicating it would double the table), `previous_prices` (most recent prior-day snapshot per card), `latest_prices` (newest snapshot, today included), `change_baselines` (the daily-change comparison point: the prior-day close, stepping one day further back when it already equals the current price — a day's row is refreshed in place, so right after the UTC rollover close == current and chips would all read $0.00 otherwise; CardDetail's per-variant Today chips mirror the rule client-side), `annotate_price_changes` (adds `priceChange` vs `change_baselines` to card dicts + records headline and variant snapshots), `attach_estimates` (adds `estimate` — the latest snapshot, i.e. the daily job's eBay sold-median — plus a `priceChange` vs the snapshot before it, to cards TCGPlayer can't price; search tiles render the value like a normal price with a muted "eBay est." label and the usual `DayChange` chip), `card_history`, `card_variant_history`. All read helpers filter to variant `""` — any new query against `card_price_snapshot` must too, or variant rows pollute it. Used by both the cards and portfolio routers — snapshots are recorded for ANY browsed card, not just held ones.
- `Backend/app/services/ebay_prices.py` — recent-eBay-sold price estimate for cards TCGPlayer can't price. Scrapes the sold-listings HTML (BeautifulSoup, `.su-card-container` tiles), drops graded/lots/proxies, and returns median/average of the most recent ungraded sales (12h `_cache`). Best-effort: any failure returns `count:0`. The `/cards/{id}/ebay-price` endpoint also refreshes today's price snapshot to a usable median (only for cards TCGPlayer can't price), so an eBay card's history point stays in step with the estimate shown — CardDetail overlays the same median onto the chart's newest point. See HANDOFF for the fetch/parse specifics.
- `Backend/app/services/tcgcsv.py` — real TCGplayer prices from the [TCGCSV](https://tcgcsv.com) nightly mirror (refreshed 20:00 UTC), for cards pokemontcg.io returns unpriced (it lags on brand-new sets): `group_id_for_set` (normalized set-name → TCGplayer group match, accents folded, `_GROUP_OVERRIDES` by set id for stubborn cases), `candidates_for_group` (products×prices join keyed by normalized card number — `"001/084"`→`"1"` — one entry per product, since a number can carry several: [Staff] stamps, merged-group collisions), `pick_candidate` (chooses the product by card name, then no-bracket-qualifier, then shortest — `require_name=True` for override paths; returns the whole entry incl. `image`, the TCGplayer product-scan URL; `pick_product` is its prices view), `product_images` (shapes a candidate's scan into a pokemontcg.io-style `images` block marked `source: "tcgplayer"` — the crawl's image substitution), `prices_for_group` (flat view, duplicates resolved to the base product), `card_prices` (pass `card_name` when known). Returns `tcgplayer.prices`-shaped dicts (`{variant: {low, mid, high, market}}`) so `extract_price`/the frontend read them unchanged. Best-effort like `ebay_prices` — any failure returns empty/`None`, never raises. Batch-only: called by the daily job's `tcgcsv_fill`, never on the request path. tcgcsv.com 401s the default python-requests UA — the session sends an identifying Mintly UA; keep it on any new call.
- `Backend/app/services/rate_limit.py` — per-IP sliding-window rate limiting as a FastAPI dependency: `rate_limit(scope, times, seconds)`; same-name scopes share one budget; over-limit → 429 + `Retry-After`. Live limits: login 10/5min, register 10/h, password change/reset 10/5min (shared `"password"` scope), forgot-password 5/h, eBay estimate 60/h, plus a shared `"api"` 120/min applied router-level on the cards + portfolio + sitemap routers — new endpoints there are covered automatically; give abuse-prone/expensive new endpoints their own extra scope. In-memory per-process (multi-worker deploys multiply budgets); `RATE_LIMIT_TRUST_FORWARDED=1` keys on `X-Forwarded-For` — only ever set it behind a proxy.
- `Backend/app/services/mailer.py` — outbound email over stdlib SMTP, configured by env (`SMTP_HOST/PORT/USER/PASSWORD`, `MAIL_FROM`); `send_email(to, subject, body, html=None)` — `html` adds a multipart/alternative part (the reset email's styled version, built by `reset_email_html` in auth.py: inline-styled tables, entity-encoded, username escaped). With no `SMTP_HOST` set it prints the text body to the console instead (dev/offline mode — the reset link lands in the uvicorn output). Raises on real send failure — the forgot-password route catches so the response never leaks whether the send happened. Production sends via Resend SMTP (`smtp.resend.com`, user `resend`, `MAIL_FROM="Mintly <noreply@mintlytcg.com>"` — see HANDOFF); never suggest Gmail SMTP for production — it stamps the sender's home IP into a `Received:` header any reset-email recipient can read.
- `Backend/scripts/snapshot_all.py` — standalone daily job: pages the full Pokemon TCG card list (`select=` of the full frontend field set) and records a `card_price_snapshot` for every priced card, so history is gap-free instead of only covering browsed/held cards. Cards with NO TCGPlayer price get two fallbacks in accuracy order: first `tcgcsv_fill` injects real TCGplayer prices from the TCGCSV mirror into the card dicts (name-aware product pick, `priceSource` mark; BEFORE the catalog upsert, so the catalog stores them like upstream prices; `--no-tcgcsv` skips), then `price_sanity_check` cross-checks every upstream-PRICED card against the same mirror and replaces blocks diverging ≥3× on a name-matched product (upstream sometimes maps the wrong product — [Staff] promos — or serves junk), then `image_fill` HEAD-checks each crawled card's image URL once (a 200 stamps `images.verified`, never re-checked; upstream's image CDN answers a MISSING image with a 404 whose body is a card-back PNG browsers render as artwork — all of mcd14/15/17/18) and re-points 404ing cards at the TCGplayer product scan (`images.source: "tcgplayer"`, re-checked each run so an upstream scan heals back; no substitute available leaves the URLs for the frontend's card-back detection), then only the still-unmatched remainder gets an eBay sold-median snapshot (newest sets first, skipping cards already snapshotted today; paced `--ebay-pause` seconds/scrape (default 5), capped at `--max-ebay` (default 2000; 0 = skip). Multi-variant cards also get per-variant snapshot rows (`record_variant_snapshots`, after the TCGCSV fill so injected blocks count). Every crawled card is upserted into `card_catalog`, and only a complete, un-truncated run (no `--max-pages`, no dropped pages) stamps the sync marker. Sale-less cards record nothing and never stop the pass; only 5 straight FAILED fetches (bot block) end it early. Ends by compacting old months to cold storage via `history_archive.compact` (`--no-compact` skips; a compaction failure never fails the run). Idempotent (per-UTC-day dedupe via `record_snapshots`); a flaky page is retried inline, then re-tried in up to 3 end-of-run sweeps with doubling cool-downs — only a page failing every sweep is dropped (run flagged incomplete), never aborting the crawl. A dropped page's cards are a different gap from priceless cards — `_collect` never saw them, so the tcgcsv/eBay fills (both driven by `crawl.unpriced`) can't reach them; the final `recover_dropped` stage closes it, recovering those cards from the catalog (any card the catalog holds that this run didn't crawl) and pricing them from TCGCSV. Gated to a full (non-`--max-pages`), already-synced run — else "uncrawled" ≠ "dropped"; respects `--no-tcgcsv`. Talks straight to the DB + upstream — the app need not be running. Scheduled via launchd (see HANDOFF).
- `Backend/app/services/history_archive.py` — price-history cold storage, stock-chart style: complete months older than `DAILY_WINDOW_DAYS` (30) are exported to gzipped CSV (`Backend/.archive/price-history/YYYY-MM.csv.gz`, gitignored; `PRICE_ARCHIVE_DIR` overrides) and the DB copy thinned to each card+variant's LAST row of the month (the "monthly close" charts keep plotting; restore handles pre-variant CSVs). Archive file is written atomically BEFORE any deletion — rows are never thinned without their file on disk; `restore_month` loads one back. Run daily by `snapshot_all.py`; manual CLI is `scripts/archive_history.py`.
- `Backend/scripts/backup.sh` — nightly backup for non-Docker hosts (bash, not venv python): one verified `pg_dump` per UTC day + a mirror of `Backend/.archive/price-history/` (part of the backup, not an extra — the DB alone no longer holds full history), local rotation, optional off-server rsync via `BACKUP_REMOTE` (warns when unset). Config from env or plain `KEY=value` lines in `Backend/.env`. Production instead crons a server-local dockerized equivalent (`~/bin/mintly-backup.sh` on pikachuserver, 03:10 UTC — same temp-file + `pg_restore --list` verify; deliberately NO off-server copy); see HANDOFF "Production deployment".
- `docker-compose.yml` + `Caddyfile` (repo root) + `Backend/Dockerfile` — the production deploy: `db` (postgres:16) / `api` (single uvicorn worker — in-memory rate limits/caches) / `caddy` (:80 — serves `Frontend/mintly/dist`, proxies `/api/*` prefix-stripped and `/sitemap.xml` to the api) / `cloudflared` (tunnel to mintlytcg.com). Frontend production builds use the committed `.env.production` (`VITE_API_BASE=/api`, same-origin — no CORS). Server secrets live in a compose-root `.env` on the server, never in the repo. Details + deploy loop: HANDOFF "Production deployment".
- `Backend/app/models.py` — SQLAlchemy models; schema is managed by Alembic (`alembic/versions/`), NOT `create_all` — model changes need a migration. `card_catalog` (one row per card: searchable columns + the full card JSON in `data` + `price_updated_at`) and `catalog_meta` (the `last_full_sync` marker) back the local catalog. `card_price_snapshot` (one row per card per **variant** per UTC day — variant `""` is the headline series, named variants exist only for cards with 2+ priced variants; composite `(card_id, snapshot_date)` index) is the app-wide price history for any browsed-or-held card; portfolio value-over-time is derived from it, there is no separate portfolio-snapshot table. Holds ~30–60 days of dailies + monthly closes; full old dailies live in the `history_archive` cold storage, not the DB. `password_reset_tokens` (sha256 of the emailed token, 30-min expiry, single-use) backs the forgot-password flow — its `user_id` FK has no cascade, so account deletion clears it explicitly.
- `Frontend/mintly/src/api.ts` — ALL fetch calls live here; pages never call `fetch` directly
- `Frontend/mintly/src/pages/` — Search, CardDetail, Portfolio, Profile, Login, ResetPassword, Home, Terms, Privacy (legal pages linked from the Footer). ResetPassword (`/reset-password`, unauthed) is one page with two modes: without `?token=` it takes an email and requests the reset link (Login's "Forgot password?" link lands here); with `?token=` (from the email) it takes the new password and routes to `/login` with a notice. Profile (`/profile`, authed) views/edits account details (username/email via `PATCH /auth/me`) + password (`POST /auth/me/password`), holds the accessibility settings, has the **Log out** button (moved off the navbar — clears the token, redirects to `/login` with the logout notice), and is where the `DeleteAccount` danger zone now lives (moved off Portfolio). The navbar's right slot is a circular profile avatar linking here when logged in, the `Login` link otherwise; the nav pill is just Search + Portfolio.
- `Frontend/mintly/src/components/` — shared UI: Navbar, Footer (brand, links, Pokemon/TCGplayer/eBay trademark disclaimer, © line — rendered on every page, on the frame below the panel), HeroSearch (home hero search pill, typewriter placeholder, navigates to `/search?q=`), PriceQtyForm (price+qty add/edit form), StatRow (label/value line), GainLoss (signed colored amount), DayChange (compact daily price-change chip, green/red/flat — used on search tiles, CardDetail, Portfolio), PriceHistoryChart (per-card price tracker: recharts chart of daily snapshots, 1M/6M/1Y/All range toggle — remount it with `key={cardId}`; pass `currentPrice` so the newest point is overlaid with the live price shown above the chart, keeping the line from contradicting it. Single-variant cards get the mint area chart; cards with 2+ variant series get one colored line per variant — fixed color per variant NAME from `variants.ts`, legend + line-end labels, `currentVariantPrices` overlay, `onData` hands the fetched history back to CardDetail for the variants table), CardImage (all card artwork — reserved 5:7 frame so there's no layout shift, muted placeholder when an image is slow/missing/failed — or when the loaded file is upstream's 404 card-back PNG, detected by its fixed 640×892 natural size since a decodable 404 body never fires `onError`; `size="tile"` default or `"detail"`. Use it for every card image, never a raw `<img>`), PageMessage (centered page state), StatusMessage (inline success/error status line — add flows, Portfolio lot errors), StructuredData (JSON-LD `<script>` block for SEO — site-wide Organization/WebSite/WebApplication graph rendered in `App.tsx` from `window.location.origin`, per-card Product markup in CardDetail), DeleteAccount (Profile "danger zone": permanently deletes the account via `DELETE /auth/me`, two-step with a typed-"DELETE" gate, then routes to `/login` with a notice). Reuse these instead of re-inlining their markup in pages.
- `Frontend/mintly/src/hooks.ts` — `useAddCard` (full add-to-portfolio flow: token check, parsing, timed status) and `useSessionRedirect` (the 401 → `/login` redirect + notice). `accessibility.ts` — device-local display prefs (reduce motion / high contrast / underline links / text size), persisted to localStorage and mirrored onto `<html>` as `data-*` attributes that `index.css` styles off; shared via `useAccessibility` (a `useSyncExternalStore` store, so Navbar's auto-hide and HeroSearch's typewriter can honor reduce-motion without a synchronous effect setState). Applied at import time so there's no flash. `format.ts` — `money()` dollar formatting. `variants.ts` — shared variant vocabulary: `PRICE_PREFERENCE`, `variantLabel`/`variantShortLabel`, the fixed per-variant chart colors (`variantColor` — assigned by variant name, never position; colorblind-validated for the dark surface), `sortVariants`, `mergeHeadline` (backfills the headline series into the preferred variant's, since pre-variant history IS that variant).
- `Frontend/mintly/src/App.css` — the **global/shared** stylesheet only (app shell `.main`/`.page`, buttons, filter/card/form primitives, utilities, the `day-change-*` chip); each component's own styles live in a co-located `*.module.css` (CSS Modules — see the styling convention below). Uses the CSS variables from `index.css` (`--bg-card`, `--border`, `--text`, `--text-h`, `--accent`, `--positive`, `--negative`, `--ink`). Theme is dark/minimal with a framed layout: a neutral near-black outer frame (`--frame`) that the translucent navbar merges into (favicon leaf logo + screen-centered nav pill), with all page content on one big rounded graphite panel (`.main`, `--bg`); cream (`--cream`) primary buttons with ink text, mint accent — keep new UI inside this palette.

## Conventions & invariants

- One `portfolio_cards` row = one purchase (a "lot"). Same card bought twice = two rows; the Portfolio page groups them by `card_id`. Do NOT merge rows or average prices on add.
- Credentials/secrets never go in query strings (they end up in server logs). Register uses a JSON body; keep it that way.
- Price-variant preference order (keep backend `extract_price` in `app/services/price_history.py` and the frontend's `PRICE_PREFERENCE` in `variants.ts` — which `getCardPrice` reads — in sync): holofoil → normal → reverseHolofoil → 1stEditionHolofoil, using `market` (falling back to `mid` when absent).
- TCG API query syntax: multi-word `name:` filters MUST be quoted (`name:"pikachu vmax"`) — bare words after a filter return HTTP 400 upstream. Free-text query parts (search text, `name`, set ids) are lowercased before building the upstream query so case variants share one cache entry; `rarity`/`type` stay exact (era-specific dropdown strings).
- New React components go in `Frontend/mintly/src/components/`, one file per component — don't define reusable components inline in page files. Pages under `src/pages/` are route entries only; if a piece of UI is (or is about to be) used by more than one page, extract it to `components/` first.
- Styling is **CSS Modules**: a component's own styles live in a co-located `Component.module.css`, imported as `styles` and applied `className={styles.camelCase}` (`vite.config.ts` sets `css.modules.localsConvention: 'camelCase'`, so the CSS files keep kebab-case names). A class used by only one component belongs in its module; only shared vocabulary (buttons, `.page`/`.main` shell, card/filter/form primitives, utilities, `day-change-*`) stays global in `App.css`. Style a global class from inside a module with `:global(.btn-outline)`; mixing a global string with a module class is fine (`` className={`filter-select ${styles.filterNumber}`} ``).
- Layout is fluid/intrinsic, not breakpoint-driven: grids reflow with `repeat(auto-fill|auto-fit, minmax(min(100%, …), 1fr))` and type/spacing scale with `clamp()`, so any width (folded phone → iPad → desktop, incl. tablet split-screen) works with no media query. The one deliberate breakpoint is the navbar's compaction (`Navbar.module.css`). Give flex children that hold inputs their own `min-width: 0`, and wrap wide tables in an `overflow-x:auto` box, so they shrink instead of overflowing.
- Authenticated frontend calls go through `authedFetch` in `api.ts` (clears token + throws `SessionExpiredError` on 401). Pages catch that error and redirect to `/login` with a notice in router state — new authed flows must do the same, via `useSessionRedirect` from `hooks.ts` (don't hand-roll the redirect/notice).
- Card searches request only the fields the frontend uses (`_CARD_FIELDS` in `app/routers/cards.py`, via the upstream `select=` param). If the frontend `Card` type grows a field, add it there too or it will arrive undefined.
- Card-list endpoints (`/search`, `/cards`, `/sets/{id}/cards`) take `?page=` and return a paged envelope `{data, page, pageSize, totalCount}` (50/page), typed as `CardPage` in `api.ts`. Don't return bare card arrays from new list endpoints.
- Backend validation uses Pydantic models with `Field` constraints (price ≥ 0, quantity ≥ 1); mirror user-facing rules client-side for instant feedback, with identical messages.
- No native `confirm()`/`alert()` dialogs: errors show as inline `StatusMessage` lines (self-clearing, 4s) and destructive actions use inline two-step confirm buttons (see `Portfolio.tsx`); account deletion adds a typed-"DELETE" gate (`DeleteAccount.tsx`) since it's irreversible.
- Backend datetimes are naive UTC: use `utcnow()` from `app/models.py` for anything stored in or compared against a `DateTime` column (snapshot dedupe is per UTC day) — never `datetime.utcnow()` (deprecated) or local `date.today()`.
- Accessibility/display preferences are **device-local, not account data**: they live in localStorage via `accessibility.ts` and are never sent to the backend (there's no user-settings column) — apply them as `<html>` `data-*` attributes styled from `index.css`, don't try to persist them server-side. Text size is implemented as a `zoom` on `<html>` (the app's sizes are mostly px, so a root font-size wouldn't scale them).
- Legal pages track reality: any change affecting what user data is stored, auth/session behavior, third-party data flows, or how prices are sourced/shown must update `Terms.tsx`/`Privacy.tsx` (and their "Last updated" dates) in the same change.
- Structured data must describe visible page content only. Mintly is a tracker, not a store, so the per-card `Product` markup (`cardJsonLd` in `CardDetail.tsx`) carries **no `offers` block** — it emits name/image/description/sku/brand only; the prices shown are third-party market/estimate figures, not Mintly listings. The static `<title>` in `index.html` and `DEFAULT_TITLE` in `CardDetail.tsx` must stay identical (CardDetail restores it on unmount).

## Gotchas

- eslint react-hooks v7 is strict: no synchronous `setState` inside `useEffect` bodies — set state in promise callbacks, or defer via `setTimeout` (see the debounce effect in `Search.tsx`).
- Browse endpoints only trust `card_catalog` after a complete `scripts/snapshot_all.py` run has stamped the sync marker — a fresh DB proxies everything upstream until then. Catalog search is ILIKE substring + newest-sets-first (subtly different from upstream's phrase matching/ordering); the smart-search parsing, set-name recognition, and word-drop fallback are unchanged.
- The card/search `_cache` survives `--reload` restarts (disk mirror, see above); it now only backs the proxy fallback path, so only a never-fetched query that misses the catalog pays the upstream cost (a few seconds — upstream latency, not a bug). The portfolio `_price_cache` is memory-only and does reset on restart.
- Upstream latency scales with the *requested* `pageSize`, not the payload: 250/page benchmarks at 20–60s with dropped connections, 50/page at 2–5s. Don't raise `_PAGE_SIZE` in `app/routers/cards.py` without re-measuring (`scripts/snapshot_all.py` keeps its own 250 deliberately — it's a retrying batch job, not a user-facing request).
- Some newer sets (2026 "Mega Evolution" era) can lack TCGPlayer price data upstream — empty `tcgplayer.prices`. The daily job fills those with real TCGplayer prices from TCGCSV (matched by set + number), so after one run they browse as normally-priced cards; the eBay sold-listings estimate is the last resort for cards TCGCSV can't match, and CardDetail's live eBay fallback still covers brand-new cards browsed before the next crawl. Upstream also backfills over time — e.g. `me1` is now fully priced upstream.
- eBay scraping is fragile by nature: `ebay_prices` seeds cookies from the eBay homepage before each search and retries once (eBay blocks cold requests with a tiny "Error Page | eBay"; a real results page is ~1MB+). `parse_sold` depends on eBay's `.su-card-container` markup and takes the price *after* the "Sold <date>" marker — if eBay restructures, it returns nothing and estimates degrade to `count:0`, never an error. Verify parser changes against live HTML.
- `Backend/.env` holds real secrets (DB URL, SECRET_KEY, API key) and is gitignored — don't read it into command output or commit it.
- Schema changes: edit `app/models.py`, then `alembic revision --autogenerate -m "..."`, review the generated file, and `alembic upgrade head`. The app no longer calls `create_all`, so an unapplied migration means missing tables/columns at runtime.
- Always verify with `npm run build` (not just eslint) — the strict tsconfig catches things lint doesn't, e.g. recharts callback param types.
- CSS Modules typos are silent: a mis-keyed `styles.foo` is `undefined`, so the element renders unstyled with no TS or build error. After any styling/className change, verify the UI in the browser — a green `npm run build` is not enough.
